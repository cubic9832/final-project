# 사용자·차량 조합 평가 실험 — candidate-v2

`ml/test` 브랜치의 독립 실험이다. `recommender` v1의 코드·학습 가중치·8001 서버는 보존한다. 이 브랜치의 React 재무 진단은 별도 8002 서버와 `/api/v2`에 연결되어 있다. `hhc`의 기존 화면과 연결은 변경하지 않았다.

React 화면으로 실행하려면 저장소 루트에서 `./ml/serve-candidates.ps1`를 실행하고, 다른 터미널에서 `npm --prefix front run dev`를 실행한다. `http://127.0.0.1:5173/financial`에서 소득·지출 → 자산·부채 → 차량 이용 → 확인을 거쳐 추천 차량을 확인한다. `/docs`는 개발자용 API 문서다. 개발 서버의 `/api/v2` 프록시를 사용하며 배포 시에는 동일 경로를 8002 서버로 전달하는 reverse proxy가 필요하다.

금액은 화면에서 만 원으로 입력하고 API에 원 단위로 전달한다. 대출 상환액은 자산·부채에서 한 번만 입력하며 잔액은 선택적인 현황 확인용이다. 연료 선호·충전 가능 여부·최소 월 여유자금을 전달한다. 추천 카드에는 가격·월 할부·월 유지비·비용 상승 후 잔여 자금·추천 사유·출처를 표시한다. 이미지가 없는 신규 모델은 준비 중 표시를 사용한다. 기존 v1 추천 결과가 남아 있으면 재무 진단으로 이동해 새로 입력한다.

## 해결 범위

- 고정 20개 차량 라벨 분류를 없애고 사용자·차량 특성 26개 → MLP 64 → 32 → 점수 1개의 조합 평가로 바꿨다. 브랜드·차량명·ID는 학습 특징이 아니다.
- 후보별 비용과 보수적 비용 시나리오를 계산해 부적합 후보를 **추론 전에** 제거한다. 후보가 없으면 정상적인 빈 목록이다. 전기차는 충전 가능을 명시한 경우만 후보가 된다.
- 정답을 **명시한 비용·선호 효용에서 어느 후보가 더 높은가**라는 쌍별 순위로 정했다. 정답 차량 하나만 강제하지 않는다.
- 특정 차량을 먼저 배정해 가상 소유자를 만드는 방식 대신, 차량 배정 없이 재무 프로필을 독립 생성한다. 모델별 실제 판매 비율을 가정하지 않는다.
- 프로필 난수 시드를 학습·검증·평가로 분리하고, 전체 모델 표기의 약 20%를 학습에서 제외해 새로운 차량 특성의 평가도 따로 수행한다.

## 데이터와 한계

기존 `data/vehicles/csv/domestic-vehicle-details.csv`의 공식 자료 자동 추출 스냅샷을 읽는다. 328행에서 가격 누락·지원하지 않는 연료·사양 식별 충돌을 제외한 **69개 모델 표기, 231개 가격 사양**이다. 하이브리드·특별판 파생 표기를 포함하므로 69개의 서로 다른 차체를 의미하지 않는다. 원본 CSV는 수정하지 않았다.

중복 식별자가 나오면 먼저 발견한 저가 행을 선택하지 않고 해당 식별자의 모든 행을 제외한다. `report.json`에 제외 행과 원본 해시를 기록한다. 원본 328행 중 97행을 제외했다. `rejected`에는 파싱 중 감지한 행이 기록되고, 그와 충돌한 최초 행 30개도 추가로 제외된다.

연비를 연결하지 못한 156개 후보는 null을 유지한다. 제조사 제원을 만들어 넣지 않고 아래 명시한 범위의 중간값·하한으로 비용을 계산한다. 결과마다 `efficiency_estimated`와 원문 URL·확인일·자동 추출 상태를 제공한다. 현재 판매 가능, 옵션·구동·좌석 조합, 최종 견적을 보증하지 않는다. 데이터가 부족한 수소 차량은 지원하지 않는다. 수입차 카탈로그도 이번 기본 후보에는 포함하지 않았다.

**합성 데이터의 가정을 바꾸어도 현실의 정답이 생기는 것은 아니다.** 이 모델은 아래 효용 함수를 근사하는 학습 실험이다. 만족도·선호의 실증 모델이나 금융 심사 모델이 아니다. 공간·좌석·안전 특성은 현재 입력 데이터가 부족해 평가하지 않는다. 기존의 ‘보유 차량 예측’ 정확도와 본 실험의 NDCG를 직접 비교하면 안 된다.

## 정답과 비용 정책

금액은 모두 원, 금리는 0.06 같은 연 비율이다. 월 지출은 주거비·생활비 등의 합계이며 기존 대출 상환과 저축을 중복 포함하지 않는다. 기존 대출 잔액보다 **실제 월 상환액**을 현금흐름에 사용한다. 선수금+비상자금은 예금을 넘을 수 없다.

- 총 구매비용: 차량 가격 × 1.07. 7%는 모든 후보에 적용한 실험 취득부대비 가정이며 실제 차종별 세금 규정이 아니다.
- 월 비용: 원리금균등 할부 + 연 주행거리 기반 에너지비 + 보험 10만 + 정비 6만 + 세금 2.5만.
- 에너지 단가 가정: 가솔린·하이브리드 1,800원/L, 디젤 1,700원/L, LPG 1,100원/L, 전기 350원/kWh. 실제 시세로 자동 갱신되지 않는다.
- 미확인 연비 범위: 가솔린 8~14, 하이브리드 14~22, 디젤 10~16, LPG 6~10 km/L, 전기 3~6 km/kWh.
- 스트레스 비용: 금리 +3%p, 미확인 연비는 범위 하한, 운행·고정 유지비 ×1.25.
- 자격 조건: 스트레스 비용을 뺀 월 잔여액 ≥ 사용자의 최소 여유자금. 목표 저축은 이미 차감한다. 일시불은 취득부대비 포함 전액을 선수금으로 충당해야 한다.

합성 효용은 `0.75 × [(1-w) × 여유자금비율 + w × 운행경제성] + 0.25 × 연료선호일치`다. 비율은 0~1로 제한한다. `w`는 출퇴근·업무 0.4, 여가·가족 0.2다. 선호 없음은 중립값 0.5다. 이용 목적이 공간·안전을 평가한다는 뜻은 아니다.

같은 사용자의 후보 중 효용 차이가 0.01 이상인 쌍을 골라 pairwise logistic loss로 학습하고, sigmoid 출력의 효용 스케일을 보조 손실로 고정한다. **rankingScore는 구매 확률·만족도 확률이 아니다.** 결과 설명은 모델의 인과적 판단 근거가 아니라 실제 비용 계산과 선호 일치 사실이다.

## 실행

저장소 루트 PowerShell에서 기존 `ml/.venv` 또는 `ml/README.md`의 환경을 사용한다. 새 환경은 `python -m pip install -e "./ml[serve,test]"`로 설치한다. 기존 editable 설치는 패키지 목록 변경을 반영하려면 다시 설치한다.

```powershell
./ml/serve-candidates.ps1
```

문서는 `http://127.0.0.1:8002/docs`에서 확인한다. 별도 터미널:

```powershell
$candidateBody = Get-Content -LiteralPath ./ml/examples/candidate-profile.json -Raw -Encoding utf8
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8002/api/v2/recommendations -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($candidateBody))
```

`GET /api/v2/recommendation-options`는 후보 수, 필수 필드, 비용 가정을 반환한다. 요청 누락·잘못된 범위는 400 Problem Details와 필드 오류를 반환한다. 잘못된 금액을 임의 기본값으로 채우지 않는다. `k`는 1~20이며, 적격 모델이 적으면 그 수만큼만 반환한다. 같은 브랜드·모델 표기는 최상위 트림 하나만 보여준다.

모든 응답은 카탈로그 수·적격 수·제외 사유·비용 가정·제약을 포함한다. 학습 특징 범위 밖의 후보에는 `outsideTrainingRange`가 표시된다. 이 표시는 신뢰도 확률이 아니며 실사용에서는 추가 검토가 필요하다.

## 새 차량 추가와 재학습

모델 출력 노드를 늘리지 않고 새 카탈로그로 추론할 수 있다. 동일 스키마의 CSV 또는 `catalog.json` 형식의 JSON을 준비한 뒤 환경변수로 지정한다. JSON의 모든 행은 양수 가격, 지원 연료, 식별자·출처·확인일이 필요하다. CSV는 동일한 정제 규칙을 적용한다.

```powershell
$env:ML_CANDIDATE_CATALOG = 'C:/path/to/reviewed-catalog.csv'
./ml/serve-candidates.ps1
```

별도 모델은 `ML_CANDIDATE_RUN`으로 선택한다. 기본 번들의 카탈로그·가중치 해시를 검증한 후 외부 카탈로그를 적용한다. 새 ID·모델명이 가능하다는 것이 새로운 가격대·연료에서 품질이 검증되었다는 뜻은 아니다. 새 연료·특징 스키마는 코드 변경과 재학습이 필요하다.

기존 실험을 덮어쓰지 않도록 새 출력 경로로 재학습한다.

```powershell
Push-Location ./ml
./.venv/Scripts/python.exe -m vehicle_matching.train --output outputs/models/candidate-v2/my-run
./.venv/Scripts/python.exe -m unittest discover -s tests -v
Pop-Location
```

`--catalog-csv`, `--seed`로 입력·난수를 선택할 수 있다. 학습 프로필 600명, 검증 150명, 평가 200명이며, 30/60 epoch 후보 중 검증 NDCG가 높은 모델만 고른다. 테스트 점수로 모델을 선택하지 않는다. 프로필·쌍별 데이터는 시드와 코드로 재생성하며 대용량 중간파일은 추적하지 않는다. 시연을 바로 실행할 수 있게 이번 작은 가중치·정규화 통계·카탈로그·보고서는 `ml/experiments/candidate-v2`에 함께 커밋했다. 후속 학습 산출물은 기존 outputs ignore 정책을 따른다.

## 평가를 읽는 법과 다음 단계

`experiments/candidate-v2/report.json`에 본 실행의 결과가 있다. NDCG@3는 **합성 효용 순위와의 일치도**다. 월비용만 정렬한 기준선과 정답 효용 계산식을 직접 사용하는 기준선(1.0)을 모두 제공한다. 이 모델이 정답 계산식보다 우수하다는 주장은 하지 않는다.

평가 프로필은 학습과 분리되어 있고, 모델 표기 단위 신규 차량 holdout도 별도로 평가한다. 연료 선호 가중치 0.1/0.5, 에너지 단가 +25%·보험료 증가·금리 스트레스 강화, 소득 구간별 결과도 기록했다. 비용 증가에 따른 적격 후보 감소는 정책 결과이며 이를 ML 정확도 향상으로 집계하지 않는다.

현실 검증을 하려면 실제 사용자의 후보 간 선호, 구매 후 월 지출과 만족도를 수집하고, 사용자 단위·시간 기준 평가로 교체해야 한다. 그 전에는 계산식만 쓰는 방식보다 ML이 실제로 더 유용하다는 근거가 없다. 이 브랜치는 후보 확장과 목표·검증 구조를 개선한 **실험 가능한 출발점**이다.
