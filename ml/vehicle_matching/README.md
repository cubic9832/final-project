# 사용자·차량 조합 평가 실험 — candidate-v2

현재 추천은 `cash-monthly-affordability-v5`다. 구매 상한은 비상자금을 제외한 현재 예금이며 월소득을 대출 가능액으로 바꾸지 않는다. 60개월·연 6% 자동 할부 가정은 제거했다. 월소득은 생활비·저축·기존 상환·차량 유지비와 최소 여유자금을 감당하는지 검사하며, 월 가용자금 대비 유지비 부담률도 점수에 반영한다. 가성비는 구매비 점수와 월 유지비 부담 점수를 절반씩 반영한다. 현금 예산의 80~100% 가격대를 우선하고, 후보가 부족하면 아래 가격대로 확대한다. 아래 과거 기록의 자동 할부 정책과 과거 CSV·모델은 당시 실험 기록으로 보존되며 현금 구매 기준으로 재학습한 결과가 아니다.

`ml/test` 브랜치의 독립 실험이다. `recommender` v1의 코드·학습 가중치·8001 서버는 보존한다. 이 브랜치의 React 재무 진단은 별도 8002 서버와 `/api/v2`에 연결되어 있다. `hhc`의 기존 화면과 연결은 변경하지 않았다.

React 화면으로 실행하려면 저장소 루트에서 `./ml/serve-candidates.ps1`를 실행하고, 다른 터미널에서 `npm --prefix front run dev`를 실행한다. `http://127.0.0.1:5173/financial`에서 소득·지출 → 자산·부채 → 차량 이용 → 확인을 거쳐 추천 차량을 확인한다. `/docs`는 개발자용 API 문서다. 개발 서버의 `/api/v2` 프록시를 사용하며 배포 시에는 동일 경로를 8002 서버로 전달하는 reverse proxy가 필요하다.

금액은 화면에서 만 원으로 입력하고 API에 원 단위로 전달한다. 대출 상환액은 자산·부채에서 한 번만 입력하며 잔액은 선택적인 현황 확인용이다. 연료 선호·충전 가능 여부·최소 월 여유자금을 전달한다. 추천 카드에는 가격·월 할부·월 유지비·차량 비용 지출 후 잔여 자금·추천 사유·출처를 표시한다. 이미지가 없는 신규 모델은 준비 중 표시를 사용한다. 기존 v1 추천 결과가 남아 있으면 재무 진단으로 이동해 새로 입력한다.

## 해결 범위

- 고정 20개 차량 라벨 분류를 없애고 사용자·차량 특성 26개 → MLP 64 → 32 → 점수 1개의 조합 평가로 바꿨다. 브랜드·차량명·ID는 학습 특징이 아니다.
- 후보별 비용과 보수적 비용 시나리오를 계산해 부적합 후보를 **추론 전에** 제거한다. 후보가 없으면 정상적인 빈 목록이다. 전기차는 충전 가능을 명시한 경우만 후보가 된다.
- 정답을 **명시한 비용·선호 효용에서 어느 후보가 더 높은가**라는 쌍별 순위로 정했다. 정답 차량 하나만 강제하지 않는다.
- 특정 차량을 먼저 배정해 가상 소유자를 만드는 방식 대신, 차량 배정 없이 재무 프로필을 독립 생성한다. 모델별 실제 판매 비율을 가정하지 않는다.
- 프로필 난수 시드를 학습·검증·평가로 분리하고, 전체 모델 표기의 약 20%를 학습에서 제외해 새로운 차량 특성의 평가도 따로 수행한다.

## 데이터와 한계

기존 `data/vehicles/csv/domestic-vehicle-details.csv`의 공식 자료 자동 추출 스냅샷을 읽는다. 328행에서 가격 누락·지원하지 않는 연료·사양 식별 충돌을 제외한 **69개 모델 표기, 231개 가격 사양**이다. 하이브리드·특별판 파생 표기를 포함하므로 69개의 서로 다른 차체를 의미하지 않는다. 원본 CSV는 수정하지 않았다.

중복 식별자가 나오면 먼저 발견한 저가 행을 선택하지 않고 해당 식별자의 모든 행을 제외한다. `report.json`에 제외 행과 원본 해시를 기록한다. 원본 328행 중 97행을 제외했다. `rejected`에는 파싱 중 감지한 행이 기록되고, 그와 충돌한 최초 행 30개도 추가로 제외된다.

연비를 연결하지 못한 156개 후보는 null을 유지한다. 제조사 제원을 만들어 넣지 않고 아래 명시한 범위의 중간값·하한으로 비용을 계산한다. 결과마다 `efficiency_estimated`와 원문 URL·확인일·자동 추출 상태를 제공한다. 현재 판매 가능, 옵션·구동·좌석 조합, 최종 견적을 보증하지 않는다. 데이터가 부족한 수소 차량은 지원하지 않는다. 원래 번들의 학습 시점에는 수입차 카탈로그가 포함되지 않았으나 아래 확장 정책으로 실행 후보에 복구했다.

**합성 데이터의 가정을 바꾸어도 현실의 정답이 생기는 것은 아니다.** 이 모델은 아래 효용 함수를 근사하는 학습 실험이다. 만족도·선호의 실증 모델이나 금융 심사 모델이 아니다. 공간·좌석·안전 특성은 현재 입력 데이터가 부족해 평가하지 않는다. 기존의 ‘보유 차량 예측’ 정확도와 본 실험의 NDCG를 직접 비교하면 안 된다.

## 정답과 비용 정책

금액은 모두 원, 금리는 0.06 같은 연 비율이다. 월 지출은 주거비·생활비 등의 합계이며 기존 대출 상환과 저축을 중복 포함하지 않는다. 기존 대출 잔액보다 **실제 월 상환액**을 현금흐름에 사용한다. 선수금+비상자금은 예금을 넘을 수 없다.

- 총 구매비용: 차량 가격. 취득부대비 7% 일괄 가정을 제거했다.
- 월 비용: 원리금균등 할부 + 연 주행거리 기반 에너지비 + 보험 10만 + 정비 6만 + 세금 2.5만.
- 에너지 단가 가정: 가솔린·하이브리드 1,800원/L, 디젤 1,700원/L, LPG 1,100원/L, 전기 350원/kWh. 실제 시세로 자동 갱신되지 않는다.
- 미확인 연비 범위: 가솔린 8~14, 하이브리드 14~22, 디젤 10~16, LPG 6~10 km/L, 전기 3~6 km/kWh.
- 월 비용: 선택한 기본 금리의 할부금 + 월 운행·고정 유지비. 비용 상승 시나리오를 적용하지 않는다.
- 자격 조건: 월 차량 비용을 뺀 잔여액 ≥ 사용자의 최소 여유자금. 목표 저축은 이미 차감한다. 일시불은 차량 가격 전액을 선수금으로 충당해야 한다.

합성 효용은 `0.75 × [(1-w) × 여유자금비율 + w × 운행경제성] + 0.25 × 연료선호일치`다. 비율은 0~1로 제한한다. `w`는 출퇴근·업무 0.4, 여가·가족 0.2다. 선호 없음은 중립값 0.5다. 이용 목적이 공간·안전을 평가한다는 뜻은 아니다.

같은 사용자의 후보 중 효용 차이가 0.01 이상인 쌍을 골라 pairwise logistic loss로 학습하고, sigmoid 출력의 효용 스케일을 보조 손실로 고정한다. **rankingScore는 구매 확률·만족도 확률이 아니다.** 결과 설명은 모델의 인과적 판단 근거가 아니라 실제 비용 계산과 선호 일치 사실이다.

## 실행

저장소 루트 PowerShell에서 기존 `ml/.venv` 또는 `ml/README.md`의 환경을 사용한다. 새 환경은 `python -m pip install -e "./ml[serve,test]"`로 설치한다. 기존 editable 설치는 패키지 목록 변경을 반영하려면 다시 설치한다.

```powershell
./ml/serve-candidates.ps1
```

문서는 `http://127.0.0.1:8002/docs`에서 확인한다. 별도 터미널:

```powershell
$candidateBody = Get-Content -LiteralPath ./ml/examples/candidate-profile.json -Raw -Encoding utf8
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8002/api/v2/recommendations -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($candidateBody))
```

`GET /api/v2/recommendation-options`는 후보 수, 필수 필드, 비용 가정을 반환한다. 요청 누락·잘못된 범위는 400 Problem Details와 필드 오류를 반환한다. 잘못된 금액을 임의 기본값으로 채우지 않는다. `k`는 1~20이며, 적격 모델이 적으면 그 수만큼만 반환한다. 같은 브랜드·모델 표기는 최상위 트림 하나만 보여준다.

모든 응답은 카탈로그 수·적격 수·제외 사유·비용 가정·제약을 포함한다. 학습 특징 범위 밖의 후보에는 `outsideTrainingRange`가 표시된다. 이 표시는 신뢰도 확률이 아니며 실사용에서는 추가 검토가 필요하다.

## 새 차량 추가와 재학습

모델 출력 노드를 늘리지 않고 새 카탈로그로 추론할 수 있다. 동일 스키마의 CSV 또는 `catalog.json` 형식의 JSON을 준비한 뒤 환경변수로 지정한다. JSON의 모든 행은 양수 가격, 지원 연료, 식별자·출처·확인일이 필요하다. CSV는 동일한 정제 규칙을 적용한다.

```powershell
$env:ML_CANDIDATE_CATALOG = 'C:/path/to/reviewed-catalog.csv'
./ml/serve-candidates.ps1
```

별도 모델은 `ML_CANDIDATE_RUN`으로 선택한다. 기본 번들의 카탈로그·가중치 해시를 검증한 후 외부 카탈로그를 적용한다. 새 ID·모델명이 가능하다는 것이 새로운 가격대·연료에서 품질이 검증되었다는 뜻은 아니다. 새 연료·특징 스키마는 코드 변경과 재학습이 필요하다.

기존 실험을 덮어쓰지 않도록 새 출력 경로로 재학습한다.

```powershell
Push-Location ./ml
./.venv/Scripts/python.exe -m vehicle_matching.train --output outputs/models/candidate-v2/my-run
./.venv/Scripts/python.exe -m unittest discover -s tests -v
Pop-Location
```

`--catalog-csv`, `--seed`로 입력·난수를 선택할 수 있다. 학습 프로필 600명, 검증 150명, 평가 200명이며, 30/60 epoch 후보 중 검증 NDCG가 높은 모델만 고른다. 테스트 점수로 모델을 선택하지 않는다. 프로필·쌍별 데이터는 시드와 코드로 재생성하며 대용량 중간파일은 추적하지 않는다. 시연을 바로 실행할 수 있게 이번 작은 가중치·정규화 통계·카탈로그·보고서는 `ml/experiments/candidate-v2`에 함께 커밋했다. 후속 학습 산출물은 기존 outputs ignore 정책을 따른다.

## 평가를 읽는 법과 다음 단계

`experiments/candidate-v2/report.json`에 본 실행의 결과가 있다. NDCG@3는 **합성 효용 순위와의 일치도**다. 월비용만 정렬한 기준선과 정답 효용 계산식을 직접 사용하는 기준선(1.0)을 모두 제공한다. 이 모델이 정답 계산식보다 우수하다는 주장은 하지 않는다.

평가 프로필은 학습과 분리되어 있고, 모델 표기 단위 신규 차량 holdout도 별도로 평가한다. 연료 선호 가중치 0.1/0.5, 에너지 단가 +25%·보험료 증가·금리 스트레스 강화, 소득 구간별 결과도 기록했다. 비용 증가에 따른 적격 후보 감소는 정책 결과이며 이를 ML 정확도 향상으로 집계하지 않는다.

현실 검증을 하려면 실제 사용자의 후보 간 선호, 구매 후 월 지출과 만족도를 수집하고, 사용자 단위·시간 기준 평가로 교체해야 한다. 그 전에는 계산식만 쓰는 방식보다 ML이 실제로 더 유용하다는 근거가 없다. 이 브랜치는 후보 확장과 목표·검증 구조를 개선한 **실험 가능한 출발점**이다.

## 현재 추천 정책 — financial-filter-ml-raw-v1 (2026-10-27)

재무 적격 필터 이후 ML 원본 출력만으로 내림차순 정렬한다. 동점은 차량 ID 오름차순이며 차종별로 가장 높은 사양 하나만 반환한다. 선호는 모델 입력으로 전달하며, 별도 규칙 점수를 최종 순위에 합산하지 않는다. sigmoid는 과거 실험·학습 호환용 predict에 남지만 서비스 정렬에는 사용하지 않는다.

응답 rankingScore는 음수도 가능한 원본 출력이며 확률·100점 척도가 아니다. rankingScoreType은 ml-raw, scorePolicy는 financial-filter-ml-raw-v1이다. 기존 integratedScore 대신 preferenceAssessment를 반환한다. 이 객체의 components는 조건별 설명용 점수·중요도이며 total·contribution 없이 rankingApplied=false를 명시한다. rankingComparison은 ml-ranked 상태와 원본 점수 차이를 제공하며 항목별 인과 기여도는 제공하지 않는다. 웹 카드와 전체 후보 조건 집계도 이 계약을 사용한다. 모델 재학습은 하지 않았다.

선호 민감도 실험은 outputs/reports/preference-sensitivity-20261027/README.md를 참고한다. 과거 가중합 비교 스크립트·보고서는 당시 정책의 실험 기록이며 현재 서비스 결과와 구분한다.

## 과거 사용자 중요도 통합 점수 — weighted-preferences-v1 (서비스 적용 종료)

기존 candidate-v2 신경망 가중치는 그대로 유지하며 **후처리 정책**으로 중요도를 통합한다. 사용자 중요도 자체를 새로 학습했다고 주장하지 않는다. 기존 report.json의 NDCG는 원래 합성 효용 모델의 평가이며 새 통합 점수의 품질 평가가 아니다.

요청 필드는 `cost_importance`, `space_importance`(정수 1~5, 기본 3), `preferred_size`(any/small/medium/large, 기본 any), `minimum_seats`(0~9, 0=미지정)다. UI는 매우 중요함=5에서 매우 중요하지 않음=1까지 표시한다. 낮은 중요도가 비싼 차·큰 차를 선호한다는 뜻은 아니다.

재무 필터는 중요도에 관계없이 적용된다. 정원이 최소 인원보다 적은 차량은 제외한다. `candidate-seating-evidence.json`은 69개 모델을 점검한 기록이며 20개 모델의 공식 정원 자료를 연결한다. 나머지는 미확인으로 유지한다. 여러 정원 사양은 모든 선택지가 최소 인원 이상이면 통과, 전부 부족하면 제외, 일부만 충족하면 좌석 확인이 필요하다. 모델별 정원 선택지는 표시 가격에 포함된 옵션을 보증하지 않는다. 레이는 TAM 2023 공식 설명서의 승용 5인승을 참고하며 밴은 적용하지 않는다. 일반 2~4인 가정을 적용할 수 없는 미확인·사양 선택이 필요한 차량은 재무 및 다른 조건을 통과한 경우에만 `conditionalRecommendations`로 반환하고 적격 수에 포함하지 않는다. 확정 추천을 우선하며 확정 추천이 k개 미만일 때만 남은 수만큼 별도 조건부 후보를 제공한다. 선호 크기 지정 시 전장 미확인 후보는 재무 조건을 충족한 경우 별도 사양 확인 후보로 반환하며 크기 점수는 부여하지 않는다. 학습 카탈로그와 가중치는 수정하지 않고 서비스 로딩 시 출처 자료를 연결한다.

크기는 실내 공간·법정 차급 대신 외부 전장만 비교한다. small은 4.2m 이하, medium은 4.2~4.8m, large는 4.8m 이상(경계 공유)이다. 선호 범위 안이면 100점, 밖이면 범위에서 1m 떨어질 때까지 선형 감소한다. 더 클수록 높은 점수가 아니다. `data/vehicles/candidate-space-evidence.json`에 기존 공식 문서의 전장 단일값과 페이지·인용문을 기록했다. 추출파일이 여러 모델에 공유되거나 단일값이 아닌 경우 제외했다. 기본 번들의 해시 검증 후 이 근거를 조인하며 외부 카탈로그에는 자동 조인하지 않는다.

가성비 총비용은 `차량 구매비 + 60개월 유지비 + 최초 60개월 내 발생한 할부 이자`다. 원금은 구매비에 이미 포함되므로 다시 더하지 않는다. 60개월보다 긴 할부의 이후 이자는 제외한다. 잔존가치, 보조금, 선택 옵션과 비용 상승률은 이 총비용에서 미반영이다. 재무 적격 검증은 기본 월 차량 비용만 사용한다.

가성비 점수는 `100 × clip(1 - 총비용 / (60개월 가용자금 + 예금 - 비상자금), 0, 1)`이다. 최소 분모는 1원이다. 통합 점수는 `(가성비점수×사용자가중치 + 크기점수×사용자가중치 + 기존ML점수×1) / 가중치합`이다. 크기 미지정이면 공간 항목과 가중치를 모두 제외한다. 기존 ML 점수에는 용도·연료 선호가 반영되어 있으며 사용자 중요도로 재학습한 점수가 아니다. 통합 점수는 확률이나 만족도 예측이 아니다.

응답 `integratedScore`에 total, components(원점수·가중치·기여도), ownershipMonths, estimatedOwnershipCost, policy, spaceEvaluated를 제공한다. 새 테스트는 중요도 교환 시 순위 역전, 인원·예산 필터 유지, 미확인 사양 처리, 원금 중복 방지, 작은 크기 선호를 검증한다.

일반 정원 미확인 차량은 사용자 지정 정책에 따라 2~4인승으로 가정하며 최소 인원 4명까지 통과한다. 실제 정원 필드는 null로 유지하고 응답의 `assumed_seat_range: [2, 4]` 및 UI 문구로 가정을 구분한다. 5명 이상은 부족으로 단정하지 않고 좌석 확인 필요 후보로 분류한다. 스타리아·카니발·GV80·렉스턴·EV9·팰리세이드·싼타페·쏘렌토 계열은 일반 가정을 적용하지 않으며 확인된 정원 자료를 우선한다. 예외 중 스타리아 Hybrid/Electric은 공식 가격표에 투어러·카고가 섞여 있고 GV80 Hybrid/Black Hybrid는 개별 근거가 부족해 미확인 상태를 유지한다. 렉스턴 뉴 아레나는 공식 통합 가격표 11페이지의 5/7인승을 사용하며 별도 써밋 4인승은 전용하지 않는다.

## 기존 전체 차량 보존 및 확장

`catalog_merge.expand_catalog`는 기존 국산 `owner-funded/configuration-catalog.json` 123개와 수입 `imported-owners/configuration-catalog.json` 18개를 기본 후보와 병합한다. 동일 식별자·가격·연료 사양은 공유하고 가격 충돌 또는 누락 사양은 기존 configuration_id를 보존한 별도 ID로 추가한다. 합계 76개 모델명·265개 사양(기존 국산 복구 16개 + 수입 18개 추가)이다. 추가된 모델명은 팰리세이드 일반 모델과 수입차 6개다. 원본은 변경하지 않으며 출처·가격 시점·원래 연료를 유지한다. 명시적 `ML_CANDIDATE_CATALOG` 재정의는 지정된 목록만 사용한다.

추론은 기존 가중치로 새 후보의 특성을 평가하며 가중치를 재학습한 것은 아니다. 기존 번들의 69개 모델명·231개 학습 스냅샷과 실행 후보 76개·265개를 구분한다. 기본 CSV로 재학습할 때도 같은 병합 함수를 호출하여 다시 누락되는 일을 방지한다. 과거 성능 보고서가 확장 후보에 대한 성능 검증을 의미하지 않는다.

MILD_HYBRID와 PHEV는 원래 연료 표기를 보존하고, 연비·전기 주행 자료가 없으므로 비용 추정과 기존 학습 특징에는 GASOLINE을 사용한다. PHEV의 충전 절감 효과를 가정하지 않는다. 이는 수입차별 정비비·전용 연비를 반영한 비용 모델이 아니다. 가격 확인일 미기록 자료에 새 확인일을 만들어 넣지 않는다. 모닝의 기존 g 1.0 연료 공란은 가솔린으로 정규화한다.

전장 자료가 없는 차량은 크기 선호 지정 시 `conditionalRecommendations`의 사양 확인 후보가 된다. 크기 가중치를 유지하되 미확인 성분에는 0점을 부여하여 확인된 크기 일치를 보상받지 않게 한다. 반환 필드 `lengthVerificationRequired`와 `seatingVerificationRequired`를 구분한다. 재무·충전 조건이 실패하면 조건부 후보에도 포함하지 않는다. 전체 목록은 `ml/reports/candidate-catalog-expanded.md`, 병합 출처 해시는 `data/vehicles/candidate-expansion-report.json`에 기록한다.

## 후보 ID별 승차 정원 등록

사용자 제공 `# 전체 차량 후보 265건 상세 목록 .txt`(승차 정원 열 포함)를 `tools/data/vehicles/import_candidate_seating.py --input <경로>`로 가져온다. 265개 후보 ID의 중복·누락과 브랜드·모델·트림·가격 일치를 검증한다. 원본 파일의 SHA256과 입력 정원 문구를 보존하며 `data/vehicles/candidate-seating-registry.json`에 등록한다. 현재 251건은 사용자 제공 값이고 14건은 기존 공식 자료와 충돌하여 공식 정원 또는 가격 페이지에 대응하는 정원을 적용했다. 사용자 제공 값을 제조사 검증값으로 표시하지 않는다.

`seats`는 기본 정원, `seat_options`는 기본 및 선택 가능한 정원이다. 기본 5인승·선택 6/7인승이면 5명까지 기본 사양으로 통과하고 6~7명은 옵션 확인 필요 후보, 8명은 제외한다. 기본 5인승·선택 4인승은 기본 사양이 5명이므로 최소 5인 조건을 통과한다. 기본 정원이 특정되지 않은 7/9인승은 최소 7명까지 통과하고 8~9명은 좌석 사양 확인이 필요하다. 옵션 변경 비용은 기본 가격에 포함시키지 않는다.

서비스 로딩과 기본 재학습 입력 준비 시 `seating.apply_seating_registry`를 적용한다. 기존 가중치·학습 카탈로그 해시는 변경하지 않는다. 정원은 현재 학습 특징을 추가하는 대신 추천 전 필터에 연결된다. API는 `registeredSeatingCount`(등록 수)와 `verifiedSeatsCount`(공식 참조 단일값 수)를 구분한다. 전체 입력/적용값 비교표는 `ml/reports/candidate-seating-registration.md`이며 전체 265건 상세 표에도 등록 정원을 추가했다.


## 비용 상승 가정 제거

현재 실행 정책은 `cost-utility-v2.3-base-cost-only`이다. 금리 +3%p, 유지비 1.25배, 연비 하한을 적용한 추가 시나리오를 제거했다. 추천 적격·초기 지급액·ML 특징·효용 계산은 기본 월 할부금과 유지비만 사용한다. `월 가용자금 - 기본 월 차량 비용 >= 최소 월 여유자금`으로 판단한다. 공개 API 비용·실행 가정과 화면에서 stress 항목을 제거했다.

과거 번들 파일을 읽기 위해 Assumptions의 stress 필드와 기존 특징 이름은 호환 목적으로만 남아 있다. 과거 필드 값을 전달해도 계산에 사용하지 않는다. 내부 `assess`의 legacy stress 반환 키는 기본 비용·잔여액과 동일하며 공개 추천 응답에서는 제거한다. 기존 가중치와 과거 평가 보고서는 재학습·재작성하지 않았다. 과거 보고서에 남은 비용 상승 실험은 현재 실행 정책이 아니다.

## 추천 단계에서 구매 금융 계획 제거

자동 초기 지급액 역산 함수와 관련 응답·화면 항목을 삭제했다. React는 선수금·할부 기간·금리를 입력받거나 요청에 포함하지 않는다. 기존 요청의 구매 금융 필드는 하위 호환을 위해 받을 수 있지만 제외 처리하며 추천에 반영하지 않는다. 추천 전에는 월 유지비 감당 여부와 인원·충전 조건을 확인하고, 차량 가격과 5년 유지비를 가성비 점수에 사용한다. 잔여 자금 예상 수치는 월 가용자금에서 예상 월 유지비만 차감하며 구매대금을 포함하지 않는다.

기존 가중치 형식을 유지하기 위한 금융 관련 특징 슬롯은 추천 시 0으로 고정한다. 기본 합성 프로필 생성도 금융 계획을 생성하지 않도록 수정했다. 이번 변경으로 가중치를 재학습하지는 않았다. 과거 학습·평가 파일은 당시 기록으로 보존한다.
# 현재 추천 정책: 재무 절대 조건 · 선호 상대 평가

현재 실행 정책은 `financial-hard-preferences-soft-v2`다. 아래 과거 실험 기록의 인원·충전 필터 및 유지비만으로 판정하는 규칙을 대체한다.

재무 적격 여부는 비상자금을 제외한 예금을 먼저 구매에 사용하고 부족분을 60개월·연 6% 할부로 가정하여 계산한다. 기존 상환·저축·월 유지비·최소 여유자금을 반영하며 선택적 `purchase_price_ceiling`을 지킨다. 과거 저장 선수금·기간·금리는 추천 입력으로 쓰지 않는다. 실제 대출 승인 판단이 아니다.

재무 적격 차량 전체에서 가성비·크기·연료·인원·용도와 ML 참고 점수를 가중 평균한다. API는 `cost_importance`, `space_importance`, `fuel_importance`, `seating_importance`, `purpose_importance`를 각각 1~5로 받는다. ML 참고 가중치는 1이다. 제원 미확인은 중립점수이고 인원 부족·충전 여부는 제외 사유가 아니다. 인원 부족과 제원 미확인은 추천 카드에 표시한다.

기본 k=3으로 서로 다른 모델을 최대 3개 반환하며 점수·확률이 낮다는 이유로 제외하지 않는다. 재무 적격 모델이 1~2개면 그 수만, 0개면 빈 `recommendations`와 `status=no-financially-eligible-vehicle`을 반환한다. `conditionalRecommendations`는 호환용 빈 배열로 남긴다. API의 기존 pair ranker 가중치를 이 작업에서 교체하지 않았으며 아래 새 MLP와는 별개다.

## 추천 조건 개선 — required-seats-preference-priority-ml-v1 (2026-10-27)

기존 `20261026-body-v1` 가중치는 유지한다. 재무 필터 다음에 최소 인원을 필수 검사한다. 기본 정원 부족은 제외하고, 정원 미확인·공식 자료 충돌·선택 좌석 업그레이드는 일반 추천 대신 conditionalRecommendations로 반환한다. 최소 인원 0은 정원 제한 없음이다.

남은 후보는 연료·차체·전장 크기 선호를 중요도 5부터 1까지 차례로 비교한다. 같은 중요도는 불일치 정도를 합산한다. 연료·차체 불일치는 1, 크기는 선호 전장 범위를 벗어난 거리/1000으로 계산하고, 전장 미확인은 알려진 길이보다 뒤로 둔다. 조건이 같으면 기존 ML 원본 점수와 ID로 정렬한다. 비용 중요도는 기존 모델 입력으로 유지하고 재무 적격 조건은 완화하지 않는다. 선호 불일치는 preferenceCompromise와 preferencePriority로 명시한다. rankingScore는 계속 원본 ML 값이므로 최종 순서가 점수 내림차순과 다를 수 있다. 최종 정책은 scorePolicy/rankingPolicy로 확인한다. rankingComparison은 preference-priority 상태를 사용한다.
