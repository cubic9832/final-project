# 구매 여력에 따른 80~100% 가격대 우선 추천

실행 정책 `budget-band-weighted-v3`를 ml/test의 추천 서비스에 적용했다. 데이터 스냅샷·main·ML 가중치는 변경하지 않았다. 이번 실험은 기존 pair ranker의 점수 위에 적용하는 명시적 추천 정책 변경이며 새 모델을 학습하거나 연결한 작업은 아니다.

## 계산과 순위

1. 각 실제 사양을 기존 재무 조건으로 먼저 검사한다. 비상자금·저축·기존 월 상환·최소 월 여유자금을 유지하고 부족 구매대금은 60개월·연 6% 할부로 계산한다. 개별 차량 유지비와 선택적 구매가격 상한도 지킨다.
2. 구매 투입 가능 예금과 남은 월 차량 예산에서 기준 유지비를 뺀 금액의 할부 현재가치를 합쳐 계산 상한을 구한다. 기준 유지비는 재무 적격 후보의 가장 낮은 예상 유지비다. 이는 최대 비교 여력의 상한이며, 더 비싼 유지비를 가진 후보는 자신의 실제 비용으로 다시 검증된 경우에만 추천한다.
3. 후보 목록에 그 상한에 가까운 가격이 없을 수 있으므로, 현재 목록에서 재무적으로 가능한 최고 가격까지를 추천 기준 예산으로 사용한다. API의 `financialUpper`와 `upper`를 구분해 공개한다. 무제한 가격의 고급 차량을 만들어내거나 임의로 예산을 올리지 않는다.
4. 기준 예산의 80~100% 구간에 있는 모델을 우선한다. 그 구간 안에서는 기존 가중 선호·가성비·ML 참고 점수로 정렬한다. 서로 다른 모델이 k개 미만이면 구간 아래에서 가장 가까운 가격부터 채우고 같은 가격에서는 가중 점수를 사용한다. 점수/확률 문턱은 두지 않는다.
5. 최종 개수는 `min(k,적격 모델 수)`다. 부적격 차량으로 채우지 않는다.

응답 `budgetPolicy`에 계산 상한, 추천 예산, 80% 하한, 구매 투입 예금, 월 차량 예산, 기준 유지비를 제공한다. 각 카드의 `budgetTier`와 추천 사유에 우선 구간 또는 낮은 가격대 보완을 명시한다. 통합 점수가 더 높아도 다른 가격 구간이면 순위가 뒤일 수 있다.

## 재현 관찰

아래는 사용자의 실제 정보와 무관한 고정 실험이다. 월 생활비 150만원·기존 상환 20만원·저축 50만원·비상자금 500만원, 연간 15,000km, 최소 월 여유자금 0원, 출퇴근/중간 크기/연료 무관, 가성비·공간·인원 가중치 2, 목적 4를 유지했다.

| 월소득 / 예금 | 우선 가격대 | 추천 사례 |
| --- | --- | --- |
| 300만원 / 1,000만원 | 2,352만~2,940만원 | 코나, 코나 Hybrid, 니로 |
| 400만원 / 2,000만원 | 6,920만~8,650만원 | Electrified GV70, EV9, EV6 GT |
| 600만원 / 3,000만원 | 1억3,998.4만~1억7,498만원 | G90 Long Wheel Base, Black, GV80 Black Hybrid(아래 구간 보완) |

같은 저가 3개가 유지되던 현상은 달라졌다. 다만 이는 지불 가능한 상한 근처를 우선하는 정책의 결과이며 고급 차량의 실내 품질이나 실제 승차감을 학습한 결과가 아니다. 최소 월 여유자금이 0이면 생활비·저축 이후 자금을 대부분 차량에 쓸 수 있다고 계산하므로 예산이 크게 나올 수 있다. 20%는 사용자와 합의한 초기 폭이지 인구 통계나 실제 소비 행동에서 검증된 값이 아니다. 더 높은 소득에서도 등록된 최고 사양을 모두 감당하면 가격대는 카탈로그 상한에서 멈춘다.

## 검증과 적용

- 우선 구간 선택, 가까운 아래 가격대 보완, 구매가격 상한, 소득·예금 증가에 따른 구간 변화, 적격 0/1개 경계 테스트 포함 핵심 테스트 34개 통과.
- 실제 추천 API 요청·응답 테스트 1개 통과.
- 프론트엔드 테스트 18개 및 프로덕션 빌드 통과.
- 8002 포트의 프로세스 명령행이 `vehicle_matching.api:app`인지 확인한 뒤 해당 백엔드만 재시작했다. 프론트엔드는 Vite 변경 반영을 사용했다.
- 실제 사용자 화면의 입력을 변경하지 않고 추천을 다시 요청해 새 `budgetPolicy`와 변경 차량을 확인했다. 이전 결과는 React 라우터 상태에 남으므로 단순 화면 업데이트만으로는 다시 계산되지 않으며 추천 요청이 필요하다.

이번 테스트 범위에서 금액 조건을 완화하지 않았다. 기존 306,429행 v4 학습 정답은 당시 정책 기록으로 보존하며, 현재 예산 구간 후처리 결과와 동일하다고 주장하지 않는다.
