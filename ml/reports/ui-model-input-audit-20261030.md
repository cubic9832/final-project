# 현재 UI와 추천 모델 연결 점검 — 2026-10-30

## 확인 범위

- 실행 모델: `20261029-v3-broad-taste-10k`, 68입력, 96모델·308사양.
- 프론트의 실제 `buildCandidateRecommendation`으로 12종 요청 생성.
- 동일 요청으로 저장 모델과 서비스 정렬을 비교. 5종은 실행 중인 5173 프록시로도 재검증.
- 모델 로더의 체크포인트·카탈로그 SHA-256 검사를 통과했다. 이 점검에서 모델이나 추천 정책을 수정하지 않았다.
- 예시 재무: 월소득 600만 원, 생활지출 150만 원, 예금 5,000만 원, 기존 대출 0원.

## 정상인 부분

금액은 만 원에서 원으로 변환된다. 연료·크기·필수 인원·취향·중요도는 요청에 전달된다.
제거한 외관 비례와 차체 형태는 각각 null과 any로 전달되며 주행거리는 15,000km다.
전기 선택 시 충전 응답이 전달된다. 기본·전기·7명 이상 요청 모두 성공했다.
기본 추천은 레이·모닝·캐스퍼, 전기 선호·충전 가능은 캐스퍼 일렉트릭·레이 EV·EV4,
7명 이상은 카니발 등이 반환됐다. 체크포인트 로딩 실패나 일괄 고정 응답은 확인하지 못했다.

## 발견 1: 새 취향은 모델이 학습하지 않았고, 별도 규칙이 모델보다 우선한다

`scenario_features.py`의 68입력에는 윤곽·가속 목표가 없다.
`ScenarioCandidateService.ranking_key`가 `(-취향일치도, -모델점수, ID)`로 정렬한다.
따라서 윤곽·가속을 선택하면 기존 모델은 일치도가 같은 후보 사이의 순서만 결정한다.
실제로 둥근 윤곽을 선택하면 원본 모델 점수 -2.2267의 아이오닉 6과 -2.4611의 Model Y가
원본 점수 2.4931의 모닝보다 먼저 표시된다. 이는 추론 실패가 아니라 추가 정렬의 결과다.

## 발견 2: 중요도가 한 항목만 선택되면 소거된다

일치도는 `sum(weight * match) / sum(weight)`다.
윤곽만 선택한 경우 `weight * match / weight = match`이므로 중요도 1과 5가 동일하다.
12종 중 roundLow와 roundHigh의 추천 9개 모델·순서·점수가 모두 같았다.
중요도는 현재 두 개 이상의 취향을 선택했을 때 상대 비중으로만 작동한다.

## 발견 3: UI의 정상 기본값이 학습 범위 밖이다

| 특징 | 현재 UI 기본 입력 | 학습 최솟값~최댓값 |
| --- | --- | --- |
| fuel_specified | 0: 연료 상관없음 | 1~1 |
| size_specified | 0: 크기 상관없음 | 1~1 |
| body_specified | 0: 제거된 차체 선호 | 1~1 |
| minimum_seats | 0: 인원 상관없음 | 4/9~7/9 |
| seats_weight | 0.6: 기본 중요도 3 | 1~1 |

위 값은 오류 없이 입력되지만 학습 데이터에서 보지 못한 조건이다.
기본 입력의 재무 적격 224사양 전부에서 이 범위 이탈이 발생했다.
학습 범위 밖이라는 사실만으로 정확도 저하를 수치화할 수는 없으나,
현재 UI 조건에 대한 검증 성능으로 기존 평가 정확도를 그대로 제시할 수 없다.

## 추가 확인

충전 질문을 보지 않은 연료 상관없음 사용자도 charging_available=false로 처리된다.
기존 모델은 이를 충전 불가로 해석하므로, 미응답과 실제 충전 불가를 구분하지 못한다.
가속 정렬에는 305사양의 합성 추정값이 사용된다. 기존 모델의 가속 학습 결과는 아니다.

## 권장 수정 순서

1. 현재 UI를 기준으로 질문·기본값·비활성/미응답 의미를 확정한다.
2. 상관없음·차체 선호 없음·인원 제한 없음·충전 미응답을 포함하는 학습 데이터를 구성한다.
3. 윤곽·가속을 학습 입력과 정답 생성에 함께 연결하고 중요도의 절대 효과를 검증한다.
4. 현재 UI 조건으로 재학습·평가한 뒤 별도 취향 우선 정렬을 제거하거나 명시적으로 분리한다.

임의의 가중치를 덧붙이거나 학습 범위를 벗어난 값을 다른 값으로 강제 치환하는 방식은 권하지 않는다.
