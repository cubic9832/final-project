# 자동 할부 제거와 현금 구매 기준 검증

ml/test에서 실제 추천 경로를 `cash-budget-weighted-v4`로 변경했다. 자동 생성하던 60개월·연 6% 대출은 제거했다. 기존 부채의 월 상환액은 사용자가 이미 부담하는 지출이므로 계속 차감한다.

- 구매 가능 상한 = 현재 예금 - 비상자금. 별도의 구매가격 상한을 지정한 경우 더 작은 값을 사용한다.
- 개별 차량 가격이 현금 상한을 넘으면 일시불 자금 부족으로 제외한다. 소득이 높아도 이 조건을 우회하지 못한다.
- 월 가용자금 = 월소득 - 생활비 - 기존 상환 - 목표 저축. 차량 유지비를 차감하고 최소 월 여유자금 이상이어야 한다.
- 추천의 할부 기간·금리·신규 월 할부금은 모두 0이다. 명시적인 대출 계산용 fixed 모드 함수와 과거 모델 파일은 삭제하지 않았지만 추천 API는 해당 모드를 사용하지 않는다.
- 현금 상한 안에서 등록된 최고 적격 가격까지를 기준 예산으로 삼아 그 80~100% 구간을 우선한다. 다른 선호는 상대 평가하고, 부족하면 아래 가격대로 최대 3개를 채운다.
- 화면에서 자동 할부 안내와 소득의 대출 환산 안내를 제거하고 현금 기준을 표시했다. 5년 소유비용 비교 기간은 총 유지비를 비교하는 별도 지표이며 할부 기간이 아니다.

## 실행 중 API에 대한 합성 입력 검증

동일하게 생활비 150만원·기존 상환 20만원·저축 50만원·비상자금 500만원으로 검사했다.

| 월소득 | 예금 | 현금 구매 상한 | 결과 |
| --- | --- | --- | --- |
| 600만원 | 3,000만원 | 2,500만원 | 코나·트랙스 크로스오버·베뉴, 모두 상한 이하 |
| 3,000만원 | 3,000만원 | 2,500만원 | 같은 현금 상한, 모두 상한 이하 |
| 3,000만원 | 0원(비상자금도 0원) | 0원 | 추천 없음 |

현금 경계·월 유지비 경계·예산 구간·선호·기존 모델 호환 핵심 테스트 35개, 실제 API 계약 테스트 1개, 프론트엔드 테스트 18개와 빌드를 통과했다. 저장소 내 tmp를 테스트 임시 경로로 사용했다. 로컬 8002 포트의 프로세스가 추천 백엔드인지 확인한 뒤 해당 백엔드만 재시작했다.

사용자 화면의 입력은 변경하지 않고 추천 요청만 다시 실행하여, 현금 예산을 넘지 않는 차량으로 갱신됐음을 확인했다. 개인 입력값은 이 보고서에 저장하지 않는다.

이번 작업은 실행 계산과 UI를 수정한 것이다. 기존 데이터 스냅샷과 ML 가중치는 그대로 보존했으며 재학습을 수행하지 않았다. 과거 할부 기준 CSV를 현금 기준 검증 데이터라고 사용하면 안 된다. main과 원본 학습 데이터도 수정하지 않았다.
