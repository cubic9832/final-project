# 현금 구매 예산 유지와 월소득의 유지비 부담 반영

실행 정책은 `cash-monthly-affordability-v5`다. 추천 서비스 코드와 카드 표시를 변경해 8002 서버에 반영했다. 이번 변경은 가중 순위 정책 수정이며 ML 가중치를 재학습하거나 기존 데이터 스냅샷을 다시 생성하지 않았다. main과 원본도 보존했다.

## 계산

- 현금 구매 상한 = 예금 - 비상자금. 월소득으로 구매 가능 금액을 늘리거나 대출을 가정하지 않는다.
- 유지비에 사용할 수 있는 월 금액 = 월소득 - 생활비 - 기존 월 상환 - 목표 저축 - 최소 월 여유자금.
- 부담률 = 예상 월 유지비 / 위 월 금액.
- 월 부담 점수 = `100 * (1 - min(1, 부담률)^2)`. 부담이 커지면 감점이 커지고, 충분히 작아지면 차이가 완만해지는 연속 점수다. 새로운 부적격 기준이나 고정 부담률 상한은 만들지 않았다.
- 구매비 점수 = `100 * clip(1 - 차량 가격 / 현금 구매 상한, 0, 1)`.
- 실제 추천의 가성비 점수는 구매비와 월 부담 점수의 산술평균이다. 기존 가성비 중요도 가중치를 이 합성 점수에 한 번 적용한다. 50:50과 제곱 감점은 초기 정책 설정이며 사용자 만족도 데이터로 추정한 계수가 아니다.
- 월 유지비를 지출하고 최소 여유자금을 지키는 기존 필수 조건은 계속 적용한다. 현금 구간 우선 및 구간 내 선호 가중 순위, 후보 부족 시 아래 가격대 보완도 유지한다.

API 각 후보의 `integratedScore.monthlyAffordability`에 월 가용자금·보호할 최소 여유자금·유지비 부담률·부담 점수·구매비 점수·합성 비중을 제공한다. 화면에는 부담률과 부담 점수, 합성 비중을 표시한다. 5년 소유비용은 비교 설명이며 신규 할부가 아니다.

## 실제 API 비교

아래는 개인의 실제 자료가 아닌 합성 입력이다. 예금 5,500만원, 비상자금 500만원, 생활비 120만원, 기존 상환 10만원, 저축 20만원, 연 30,000km, 선호 연료 가솔린, 가성비 중요도 5, 연료 중요도 1을 고정했다. 크기와 인원은 미지정이다.

| 월소득 | 현금 상한 | 추천 | 월 유지비 부담률 |
| --- | ---: | --- | ---: |
| 210만원 | 5,000만원 | 코나 Electric·EV5·EV4 | 63.24% |
| 600만원 | 5,000만원 | K8·그랑 콜레오스·싼타페 | 13.20% |

낮은 소득에서는 월 60만원의 가용자금 중 유지비 부담이 작아지는 후보가 유리했다. 소득이 높아지면 유지비 차이에 대한 감점이 줄어, 가솔린 선호를 충족하는 후보가 올라왔다. 모두 5,000만원 이하, 할부 기간 0개월, 최소 여유자금 조건 충족을 실제 응답에서 검증했다. 요청과 응답 예시는 `tmp/ml-test-servers/monthly-income-comparison.json`에 있다.

이는 어떤 소득 변화에도 차량이 반드시 바뀐다는 보장은 아니다. 다른 합성 입력인 예금 6,000만원·비상자금 500만원·연 15,000km에서는 월소득을 250만→750만원으로 바꿔도 GV70·팰리세이드·더 뉴 그랜저가 유지됐다. 대신 유지비 부담률은 45.8%→6.7%, 부담 점수는 약 79.0→99.6으로 달라졌다. 선호와 상대 비용 우위가 유지되면 동일 추천이 타당할 수 있다.

현재 카탈로그 사양 265건 중 190건은 연비 미확인으로 동일 연료별 가정 비용을 사용한다. 같은 연료 후보의 유지비가 같다면 월소득으로 그 후보 사이를 구별할 수 없다. 이번 작업에서 차량별 연비·승차감·편의성 수치를 임의로 만들어 넣지 않았다.

## 검증

- 고정 ML 점수·동일 가격에서 소득만 바꿨을 때 저유지비 후보와 선호 연료 후보의 순위가 전환되는 단위 테스트 통과.
- 저축·기존 상환·최소 버퍼의 부담률 반영, 유지비와 정확히 같은 월 여력 경계, 여력 0인 사례의 추천 없음 검증.
- 핵심 테스트 38개, 실제 API 계약 테스트 1개, 프론트엔드 테스트 18개 및 빌드 통과.
- 현재 사용자 화면은 입력 중인 재무 진단 페이지이므로 추가 화면 탐색으로 입력 상태를 변경하지 않았다. 다음 추천 요청부터 새 정책을 사용한다.

현재 모델은 기존 pair ranker를 참고 점수로 사용한다. 새 가중치 정책의 개선을 실제 사용자 만족도나 새 ML 모델의 예측 성능 개선이라고 해석하지 않는다.
