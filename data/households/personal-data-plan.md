# 개별 재무 데이터 확보 및 더미 데이터 계획

확인일: 2026-10-14. 현재 개별 응답 원자료는 확보하지 못했다. 기존 CSV는 집단 통계이며 아래 계획의 실제 개인 데이터가 아니다.

## 1. 공식 원자료 접근 확인 결과

| 경로 | 확인 결과 | 다음 확보 조건 |
| --- | --- | --- |
| [MDIS](https://mdis.mods.go.kr/bbs/boardList.do?boardId=BBSMSTR_000000000001) | 공식 FAQ에서 다운로드에 로그인이 필요하며 CSV 형식 선택이 가능함을 확인 | 로그인된 다운로드 서비스에서 조사·연도·제공항목·이용조건 확인 후 원자료와 코드북 확보 |
| [한국노동패널](https://www.kli.re.kr/klips/) | 가구·개인 자료 안내와 공개용 자료 메뉴 확인. 공개용 메뉴는 경고 페이지를 반환하여 파일 확보 실패 | 공개용 원자료 접근 후 개인·가구 연결 키와 소득·자산·부채·소비 변수 확인 |
| 한국복지패널 | 홈페이지 요청 실패. 제공 범위·다운로드 조건 미확인 | 대체 후보로 남기며 확보했다고 주장하지 않음 |

공식 다운로드와 코드북을 우선한다. 로그인·승인 제한을 우회하지 않는다. MDIS에서 가계금융복지조사와 가계동향조사를 우선 조사하되, 제공 여부와 필요한 세부 변수는 로그인 후 확인해야 한다.

실제 자료를 확보하면 같은 조사 내 같은 응답자/가구에 연결된 값만 사용한다. 서로 다른 조사의 가구를 소득 분위나 연령이 같다는 이유로 연결하지 않는다. 가구 소득을 개인 실수령액으로 변환하지 않는다. 가구 공동 예산과 개인 예산을 별도 표시하고 코드북에 없는 변수를 임의로 실제값처럼 채우지 않는다.

## 2. 현재 진행할 더미 데이터의 목표

목표는 차량 예산 계산, 추천 흐름, 입력 검증과 스트레스 시뮬레이션 구현이다. 초기에는 실제 연체 확률·대출 승인 예측을 학습 목표로 삼지 않는다. 더미 데이터로 얻은 성능은 합성 환경에서의 성능으로만 보고한다.

1차로 독립 프로필 1,000개를 생성해 분포와 회계 관계를 검토한다. 통과 후 10,000개로 확대한다. 이 개수는 구현·실험 규모이며 통계적 신뢰도나 실제 예측 정확도를 보장하는 표본 수가 아니다.

## 3. 데이터 구조

모든 금액은 원, 기간은 명시한다. 공통으로 profile_id, budget_scope(개인/가구), is_synthetic, generator_version, seed를 저장한다.

| 파일 | 필드 |
| --- | --- |
| profiles | 연령대, 취업 형태, 가구원 수, 부양 인원, 주거 형태, 월 실수령 소득, 추가 소득, 인출 가능한 예금, 묶인 보증금, 비상금 목표 |
| expenses | 주거비, 식비·생활비, 통신비, 교통비, 보험료·기타 고정비, 선택적 소비, 목표 저축; 각 항목 월 기준 |
| loans | 대출 종류, 잔액, 연 금리, 남은 개월 수, 상환 방식, 월 원금·이자; profile_id로 연결 |
| vehicle_scenarios | 실제 차량/트림 식별자, 가격, 선수금, 할부 기간, 가정 금리, 연 주행거리, 보험료·정비비 가정, 현재 교통비 중 대체 가능한 금액 |
| simulation_results | 차량 구매 후 월 잔여액, 현금 비상금 유지 기간, 소득 감소·금리 상승 시 잔여액, 규칙 기반 예산 초과 여부 |

현재 프런트 입력 income/extraIncome, housing/fixed/living/loan/transport/phone, savings와 assets.deposit/emergency/downPayment에 매핑한다. 현재 함수의 금액 단위는 연결 전에 화면 표시까지 확인하고 원에서 변환한다. 기존 함수의 연 6%·월 유지비 20은 가정값이므로 학습 정답으로 복제하지 않는다.

## 4. 생성 순서와 관계

1. 취업·주거·부양 상태를 생성한다. 초기 집단 구성 비율은 생성 설정에 가정으로 기록한다.
2. 상태에 조건부로 소득과 소득 변동성을 생성한다. 집단 평균은 대략적인 규모 점검에만 사용한다. 개인 분포·분산을 관측한 것으로 간주하지 않는다.
3. 주거·부양 상태와 소득을 바탕으로 항목별 소비를 생성한다. 항목마다 독립 난수를 넣는 대신 공통 생활 수준 요인과 잔차를 사용한다. 적자 가구도 허용한다.
4. 무대출/대출 보유 상태를 먼저 생성하고 잔액·금리·기간·상환 방식으로 월 상환액을 계산한다. 원리금균등/원금균등/만기일시를 구분한다.
5. 현금성 자산과 묶인 자산을 분리한다. 선수금은 인출 가능한 자금과 비상금 제약 안에서 결정한다.
6. 확보한 실제 차량 가격·연비와 결합해 구매 시나리오를 만든다. 금리·보험료·정비비 등 미확보 값은 가정임을 기록한다.
7. 차량 할부·유지비와 대체되는 기존 교통비를 반영하여 구매 후 잔여액을 계산한다. 소비에 포함된 대출 상환액을 다시 빼는 중복을 막는다.

고소득·고부채, 저소득·고자산, 소득 불안정, 무대출, 적자, 비상금 부족 사례를 별도 검증 세트에 포함한다. 검증용 극단 사례 비중은 일반 생성 분포와 분리한다.

## 5. 검증과 ML 실험 조건

- 대출 상환식, 금액 단위, 예산 회계식, 선수금·비상금 제약을 검증한다. 결측과 0을 구분한다.
- 기존 공식 집단 통계와 평균 규모를 비교하되 집단 평균 일치만으로 개인 분포의 현실성을 인정하지 않는다. 가정한 분산·상관관계도 보고한다.
- 같은 프로필에서 파생된 여러 차량 시나리오는 모두 같은 학습/검증/평가 구간에 배치한다. 프로필 기준 70/15/15 분할을 초기 설정으로 사용한다.
- 규칙으로 만든 예산 초과 여부는 규칙의 산출물이다. 이를 예측하는 모델은 규칙 모방 실험으로 표시한다. 먼저 계산식 기준선과 비교하여 ML을 추가할 이유를 확인한다.
- 유지비 예측이나 실제 구매 후 재무 부담 예측을 주장하려면 해당 실제 결과 관측값을 별도로 확보한다. 단순 차량 매칭 건수 증가를 독립 개인 표본 증가로 계산하지 않는다.

## 6. 구현 산출물과 완료 기준

생성 설정 파일(분포·관계·금리·비용 가정), 재현 가능한 생성기, 위 5종 CSV, 컬럼 사전, 검증 보고서를 만든다. 동일 seed로 동일 결과가 나오고 회계 검증을 통과하며 모든 가정·합성 표시가 보존되면 기능 개발용 1차 데이터 완료로 본다.

실제 원자료가 확보되면 코드북을 기준으로 단위·결측·가중치를 정리하고 관측 가능한 공동 분포를 보정한다. 실제 관측과 합성 보충 값은 필드별 출처로 구분한다. 데이터 재배포·저장소 공개는 해당 자료 이용조건 확인 후 결정한다.
