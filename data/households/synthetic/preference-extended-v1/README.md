# 기존 학습 입력 + 네 가지 선호 확장

입력 확장 단계의 보존 묶음이다. 모든 행에 차량 결과를 채운 최신 완성본은 `../preference-complete-v1/combined_training.csv`다. 재무 입력을 보존해 선택 없음이 남아 있는 중간 수정본은 `../preference-relabelled-v1/combined_training.csv`에 있다. 각 단계의 타깃을 혼합하지 않는다. 원본 `data/seed`와 과거 candidate-choices/v3 실험 파일은 수정하지 않았다.

## 기존 데이터 보존

기존 데이터 196,000행 전체를 확장했다. `existing/domestic-car/owners.csv` 10,000행, `existing/imported-car/owners.csv` 6,000행, `existing/domestic-extra-90000/owners.csv` 90,000행, `existing/imported-extra-90000/owners.csv` 90,000행이다. 각 파일은 기존 37개 컬럼 뒤에 아래 네 컬럼만 추가한 복사본이다. 원본 모든 셀 값과 행 순서를 대조했다. 같은 폴더의 purchases.csv는 각 원본 구매자금내역을 바이트 그대로 복사했다. 원본과 확장본의 원래 컬럼에는 수치 반올림·결측 보정·데이터 분할 변경을 하지 않았다. main과도 CSV 셀 전체를 비교했으며 Git의 줄바꿈 차이는 무시했다. 기존 16,000행에 추가했던 값과 신규 생성분은 동일 seed로 유지한다.

- 가성비중요도_1부터5: 정수 1~5
- 선호크기: 작음/중간/큼
- 선호연료: 가솔린/하이브리드/디젤/LPG/전기/상관없음
- 최소탑승인원_명: 정수 인원

기존 차량을 보고 선호를 역으로 정하지 않았다. 기존 프로필 ID·용도·새 seed만 이용해 독립 생성한 합성 보충값이며 관측된 선호나 기존 구매의 원인을 뜻하지 않는다. 기존 구매와 모든 선호가 일치하도록 강제하지 않았다. 보충 규칙은 차량을 선택한 코드가 아니므로 기존 선택이 신규 재무·좌석 정책을 통과한다는 보장도 하지 않는다. 기존 파일의 생성규칙_버전/난수_시드는 원본의 값으로 보존하고, 추가 네 값의 버전·seed는 이 묶음의 generation_config.json에 따로 기록한다.

## 공통 학습 테이블

- existing_training.csv: 기존 196,000행의 실제 학습 입력을 프로필 ID로 결합한 테이블. 원본 전체 컬럼을 대체하지 않는 공통 입력 뷰다.
- new_training.csv: 새로 생성한 10,156행. 아래 8개 기존 입력과 네 추가 항목, 식별자·타깃·출처를 모든 행에 채웠다.
- combined_training.csv: 위 두 테이블을 같은 컬럼 구조로 합친 206,156행.
- examples.csv: 기존 5행과 신규 12행의 읽기용 예시.
- vehicle_identity_map.csv: 후보 사양 ID 265개와 모델 라벨의 대응표. 브랜드·모델명이 기존과 정확히 같을 때만 OWN 라벨을 재사용한다. 나머지는 NEW 라벨로 구분하고 비슷한 이름을 임의로 합치지 않는다.
- generation_config.json / validation_report.json: 원본 해시·seed·가정·검증 결과.

기존 입력명을 그대로 사용한다: 개인_평균월실수령소득_원, 개인_현금성자산_원, 개인_평균월주거비_원, 개인_평균월기타생활소비_원, 기존대출잔액_보정전_원, 기존월상환액_보정전_원, 연간_주행거리_km, 차량_이용목적.

기존 구매 전 부채·월 상환액은 반드시 purchases.csv의 보정전 필드에서 가져온다. owners.csv의 차량 구매 후 부채·월 상환액과 혼동하지 않는다. 원본에는 개인_평균월저축액_원 등이 있지만 기존 ML의 8개 입력이 아니므로 공통 테이블에 임의로 더하지 않았다. 신규 생성의 비용 계산에는 합성 저축·여유자금·비상자금·구매자금 가정을 사용한다. 이 가정은 공통 입력만으로 완전히 설명되는 선택이 아님에 유의한다.

신규 행의 주거비는 차량 선택과 무관한 별도 seed로 생활지출 합계의 20~50%를 배정하고 나머지를 기타 생활소비로 둔다. 둘의 합은 기존 비용 계산에 사용한 월 생활지출과 정확히 같다. 부채 잔액과 월 상환액은 구매 전 값을 사용한다. 신규 입력 숫자는 정수이며 원·km 단위를 유지한다. 신규 선택 규칙은 generate_candidate_choices.py의 v3 정책(60개월·연 6% 가정, 필수 정원·월 부담·선택적 가격 상한, 크기·연료는 선호, 충전 환경 무시)을 따른다.

조건을 충족하는 차량이 없으면 타깃을 `NO-CHOICE`, 모델을 `선택없음`, 브랜드를 `해당없음`으로 명시한다. 빈칸을 없애려고 차량을 강제로 배정하거나 0원 차량을 만들지 않는다. ‘모든 행을 채움’은 실제 차량을 반드시 선택한다는 의미가 아니다.

## 검증과 학습 시 주의점

원본 모든 셀 보존, 원본 purchases 바이트 보존, 공통 입력 결측 0건, 프로필 ID 중복 0건, 동일 재무 그룹의 학습/평가 누수 0건을 검사한다. 신규 필수 조건 위반과 신규 데이터 내 보류 조합 누수도 검사한다. 실행 브랜치는 ml/test로 제한하며 main의 커밋과 모든 입력 파일 해시가 작업 중 바뀌지 않았는지 검사한다. 추가본은 대용량 원본을 순서대로 읽고 저장 결과를 다시 원본과 대조한다.

기존 분할은 그대로 유지한다. 신규 데이터만의 새선호조합평가 조합이 기존 합성 보충값에는 존재할 수 있다. 따라서 combined_training 전체에 대해 그 조합이 미학습이라고 주장하지 않는다. 해당 겹침 수는 validation_report.json의 combined_combination_overlap에 기록한다. 신규 데이터만으로 학습하는 평가와 전체 통합 평가를 구분해야 한다.

기존 학습 코드가 확장 existing/ 폴더를 읽으면 기존 8개 입력으로 동일하게 로딩되지만, 네 새 입력은 아직 모델에 자동 반영되지 않는다. combined_training.csv는 별도 통합 스키마로 향후 전처리 연결이 필요하다. 이번 작업에서는 재학습·서비스 교체를 하지 않았다. 실제 구매 확률·시장 비율로 해석하지 않는다.

재현: `python -m tools.data.households.extend_training_preferences`

검증: `python -m unittest tools.data.households.tests.test_training_preferences tools.data.households.tests.test_candidate_choices`
