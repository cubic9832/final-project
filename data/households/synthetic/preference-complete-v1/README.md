# 모든 행에 차량을 연결한 완성본

이 묶음은 이전 단계의 보존본이다. 여유자금·보정 상한·선호 우선·제원 보완을 적용한 최신 학습본은 `../preference-quality-v1/combined_training.csv`에 있다.

후속 전수 점검에서 필수 조건 위반은 없었지만, 최소 소득 보정에 따른 예산 경계 집중·선호 불일치·수입차 선택 부재가 확인됐다. `complete_quality_audit.md`를 함께 확인해야 하며, 모든 행에 차량이 있다는 사실을 최종 추천 품질 보증으로 해석하지 않는다.

현재 사용할 완성 데이터는 이 폴더의 **combined_training.csv**다. 206,156행 전체에 차량 사양 ID·모델·트림·가격·연료·비용 결과가 있다. 선택 없음과 빈칸은 0건이다. main과 data/seed, 이전 합성 데이터의 CSV는 변경하지 않았다. 작업은 ml/test에서만 수행했다.

## 파일

- combined_training.csv: 전체 완성본. 기존 입력·선호·선택 결과와 보정 전후 값을 포함한다.
- examples.csv: 입력 유지, 월소득 보정, 가격 상한 조정 사례를 각 10개씩 담은 작은 예시.
- adjustments.csv: 변경한 입력 항목별 프로필 ID·이전 값·새 값·이유. 소득과 가격 상한을 모두 바꾼 행은 두 건으로 기록한다.
- validation_report.json: 전체 검증과 보정 규모.
- generation_config.json: 사용자 승인 범위·seed·원본 해시·보정 정책.
- catalog.json / vehicle_identity_map.csv: 실제 선택 사양 스냅샷과 라벨 연결.

## 변경 기준

사용자가 ‘필요한 재무 값도 최소한으로 보정하고 변경 내역 기록’을 선택한 범위에서 완성본만 보정했다. 기존 source CSV는 읽기만 했다.

네 선호(가성비 중요도·크기·연료·최소 인원)는 모두 보존했다. 주거비·생활소비·현금성 자산·기존 부채 잔액·월 상환액·주행거리·용도도 보존했다. 바꾼 재무 입력은 월 실수령소득뿐이며, 후보가 전혀 없던 가격 상한은 필요한 경우에만 확대했다. 이 소득은 실제 소득 추정·복원이 아니라 학습 사례 완성을 위한 합성 보정값이다.

모든 입력의 후보 충족 여부를 먼저 검사해 부족분을 계산하고, 같은 재무조건그룹번호 전체에 필요한 최대 보충액을 공통 적용한다. 원래 가격 상한을 사용할 수 있으면 유지하며, 정원·예산과 충돌할 때만 필요한 최소 가격까지 확대한다. 이 계획을 확정한 다음 차량을 선택한다. 선택한 차량을 보고 선호를 역으로 정하지 않는다.

월소득 보충액은 원래 저축·기존 상환·생활비·월 여유자금 하한을 유지하면서 적어도 한 후보의 월 할부금과 유지비를 감당하는 데 필요한 금액이다. 정확한 계산 경계에서 부동소수점의 -0.0으로 탈락하지 않도록 1원 여유를 더한다. 같은 그룹에 더 부담이 큰 이용 조건이 있으면 그 조건에 맞는 공통 보충액이 적용된다. 그룹 보정 후에는 원래 가격 상한을 다시 검사해 불필요한 상한 변경을 줄인다.

선택 규칙은 이전 preference-relabelled-v1과 같다. 알려진 정원·월 부담·가격 상한을 필수로 검증하고, 비용·크기·연료·용도 점수를 종합해 최고점과 2.5점 이내 모델 중 선택한다. 동일 조건의 다양성은 가능한 후보가 여럿일 때만 허용한다. 선호가 필수 조건이 아니므로 비용·다른 선호와의 절충은 남을 수 있으며 선택설명에 기록한다. 최저 보정에 가까운 행은 선택 가능한 저비용 차량이 적을 수 있다.

할부는 비교용 60개월·연 6%, 기존 에너지·보험·세금·정비 가정을 사용한다. 추가 취득부대비·보조금·선택 옵션·잔존가치는 미반영이다. 충전 환경은 사용하지 않는다. 미확인 제원을 임의로 생성하지 않으므로 기존 제원 부족에 따른 후보 편향 한계도 유지된다.

## 결과

- 206,156행 전부 추천 차량 있음.
- 이전 선택 없음 74,880행을 모두 채움.
- 월소득 보정 74,848행, 가격 상한 조정 252행. 둘은 중복될 수 있으며 변경 입력이 있는 행의 합집합은 74,996행이다.
- 원래 차량이 있었던 116행도 같은 재무 그룹을 일관되게 유지하기 위해 함께 보정했다.
- 월소득 보정 중앙값 339,016원, 최대 5,506,395원. 1,739행은 보충액이 원래 월소득보다 크다. 이 사례는 원래 조건과 차이가 큰 합성 사례이며 adjustments.csv와 보정 전 값으로 식별할 수 있다.
- 네 선호와 월소득 외 기존 ML 입력 변경 0건. 동일 재무 그룹의 재무 정보·분할 일관성을 재검사했다.
- 선택 없음·결측·중복 ID·필수 조건 위반 0건. 선택 비용은 별도의 스칼라 계산으로 검증하고, 저장 후 다시 읽어 원본의 유지 대상 셀과 행 순서를 전수 비교했다.

## 학습 사용

generation_config.json의 제외 항목을 지켜 보정 전 값·원래 차량·변경 여부·점수·선택 후 비용 등을 입력에 넣지 않는다. 수정 후 소득을 사용해야 하며 원래 소득을 섞지 않는다. 기존 8개 입력과 네 선호 외에도, 선택에 사용한 월저축액·비상자금·구매투입가능자금·월 여유자금·가격 상한이 행에 기록되어 있다. 학습 시 필요한 조건으로 함께 연결해야 숨은 판단 기준이 생기지 않는다.

전체를 추천 가능한 사례로 만든 데이터이므로 실제 서비스의 추천 불가능 상황을 학습·평가하는 자료는 아니다. 원래 재무 분포를 보존한 평가에는 이전 데이터와 no_choice_analysis를 별도로 사용한다. 전처리와 모델 가중치는 이번 작업에서 재학습·교체하지 않았다.

재현: `python -m tools.data.households.complete_preference_choices`

새 입력 묶음 처리: `python -m tools.data.households.complete_preference_choices --source <같은형식의입력폴더> --output <새완성본폴더>`

향후 같은 형식의 묶음도 입력 적격 보정 계획을 먼저 세우고, 모든 행의 차량 결과를 검증한 뒤 저장한다. 차량을 배정하지 못하면 빈칸을 출력하지 않고 오류로 중단한다.

핵심 검증: `python -m unittest tools.data.households.tests.test_complete_choices tools.data.households.tests.test_preference_relabeling`
