# 한글 가상 차량 선택 데이터 — v2

`choices.csv`는 모든 열 이름과 용도·크기·연료·데이터 구분 값을 한글로 표시한다. 차량 고유 이름·트림·식별자·버전은 보존한다. 숫자 열은 정수이며 금액은 원, 연간 주행거리는 km다. 입력 금액과 거리를 먼저 반올림한 뒤 그 값으로 적격과 점수를 계산한다.

## 확인할 파일

- `choices.csv`: 10,280행. 한글 데이터 본문.
- `catalog.json`: ml/test의 76개 모델명·265개 사양과 원본 출처 스냅샷. 원본 연비 등 소수점 제원은 변경하지 않는다.
- `generation_config.json`: 생성 설정·한영 필드 대응표·카탈로그 해시. 계산용 소수점 설정은 원래 정밀도를 보존한다.
- `validation_report.json`: 데이터 분할·충돌·적격·다양성 검사 결과. 내부 통계는 원래 정밀도를 보존한다.

재현: 저장소 루트에서 `python -m tools.data.households.generate_candidate_choices`.
검증: `python -m unittest tools.data.households.tests.test_candidate_choices`.
기본 seed=20261021, 재무 그룹 1,000개, 선호 최대 3종, 동일 입력당 선택 4회다. 보류 조합을 학습·검증에서 제거한 결과 994개 재무 그룹이 남는다.

## 충돌 방지 규칙

1. 재무 정보 전체 → 용도·탑승 인원·크기·연료 선호 전체 → 적격 판정 → 확률 선택 순서다. 선택 차량을 보고 입력을 수정하지 않는다.
2. 가족 이동은 최소 4·5·6명, 다른 용도는 1·2·4명으로 생성한다. 5명은 중간·큰 크기, 6명은 큰 크기만 생성한다. 이 관계는 합성 데이터의 운영 가정이다.
3. 충전 불가능한 사람에게 전기 선호를 부여하지 않는다. 선택 차량은 지정한 연료와 일치해야 한다. 연료 미지정이면 모든 지원 연료를 검토하되 전기차는 충전 가능이 필요하다.
4. 선택 차량은 지정한 크기 범위 안에 있어야 한다. 작음 2,500~4,200mm, 중간 4,200~4,800mm, 큼 4,800~6,000mm이며 경계를 공유한다. 외부 전장 기준으로 실내 크기를 보증하지 않는다.
5. 기존 월 유지비·월 여유자금·최소 정원 필터를 통과해야 한다. 전장 미확인 또는 좌석 옵션 확인이 필요한 후보를 확정 선택으로 만들지 않는다. 기존 서비스의 미확인 일반 차량 2~4인 가정은 그대로 따른다.
6. 조건에 맞는 후보가 없으면 선택 차량 칸을 비워 둔다. 크기·연료·정원 조건을 몰래 완화하거나 사람의 입력을 바꾸지 않는다.

현재 선택 없음은 5,384행이다. 예산 부족 외에도 카탈로그의 전장 미확인, 좌석 조건, 크기·연료 조합의 후보 부족이 포함된다. 265개 사양을 보존하지만 모든 모델에 선택 건수를 강제로 배정하지 않는다.

## 읽는 방법

`재무조건그룹번호`가 같으면 재무 정보가 같다. `재무선호그룹번호`가 같으면 선호까지 같으며 선택을 네 번 독립 반복한다. 가성비·공간 중요도는 1~5로 높을수록 중요하다. 낮은 가성비 중요도가 고가 차량 선호를 의미하지 않는다.

`선택확률_만분율`은 10,000이 100%다. 예를 들어 411은 4.11%이며 CSV에는 정수 411로 저장한다. `선택차량점수_100점`, `최고후보점수_100점`은 내부 0~1 효용을 100점으로 바꿔 정수 반올림한다. 표시된 확률과 점수는 읽기용이며 내부 추첨은 반올림 전 값을 사용한다.

`가상기존부채잔액_원`은 기존 대출 월 상환액×36이라는 합성 가정이다. 적격 판정에는 월 상환액만 사용한다. 사용하지 않는 선수금·할부 기간·금리·금융 모드 열은 CSV에서 제외했다. 추천 모드이므로 구매대금 조달 능력까지 확인한 데이터는 아니다.

효용은 기존 가성비·크기 통합점수(ML 성분 0.5 고정) 80%, 용도별 전장 일치 12%, 연료 일치 8%다. 용도 목표 전장은 출퇴근 4,100 / 가족 4,750 / 여가 4,900 / 업무 4,600mm, 목표와 1,500mm 차이에서 일치 점수 0이다. 이는 관측된 용도 적합성이 아닌 합성 가정이다. 모델별 최고 효용 사양 하나를 남기고 softmax 온도 0.055로 추첨한다. 따라서 필수 조건을 지키면서 동일 입력에도 여러 선택이 가능하다.

## 학습·평가 구분

재무 그룹별 학습/검증/평가 70/10/20을 먼저 배정한다. 가성비 중요도·크기·용도 조합 중 고정 규칙으로 약 20%를 보류해 학습·검증에서는 제거하고 평가 재무 그룹의 `새선호조합평가`에만 배정한다. `새재무상황평가`는 새로운 재무 상황, `새선호조합평가`는 새로운 재무 상황과 보류 선호 조합을 평가한다. 같은 사람의 반복 선택은 여러 구간에 걸치지 않는다.

적격 위반·입력 선호 충돌·재무 그룹 누수·보류 조합 누수 모두 0건이다. 같은 입력에서 여러 모델이 선택된 선호 그룹은 1,022개다. 이는 생성 규칙 검증이며 학습 모델의 일반화 성능 검증은 아니다. 기존 모델 가중치와 추천 서비스는 변경하지 않았다.

학습 시 번호·데이터구분·선택 결과·확률·점수·후보 수·버전은 입력에서 제외한다. 재무·선호 열만 입력으로, 선택 차량은 가상 타깃으로 사용하고 선택 없음은 별도 처리한다. 실제 구매 기록이나 시장 점유율로 해석하지 않는다. 현재 학습기는 이 한글 CSV를 자동으로 읽지 않는다.
