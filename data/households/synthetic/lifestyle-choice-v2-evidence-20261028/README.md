# 근거 기반 차량 특성과 합성 사용자 선택 v2

이 자료가 난수 차량 특성을 사용하던 v1을 대체한다. 차량 특성은 실제 자료에서 만들고,
사용자의 선호·중요도와 확률적 선택만 합성한다. 차량 323개 사양, 107개 모델군을 포함한다.
기존 모델 카탈로그 282개 + 스포츠카 보강 22개 + 고급 차량 조사 후보 19개다.

```powershell
$env:PYTHONPATH='ml;.'
ml/.venv/Scripts/python.exe -m tools.data.households.generate_lifestyle_choices --output data/households/synthetic/lifestyle-choice-v2-new --groups 20000 --seed 20261028
ml/.venv/Scripts/python.exe -m unittest tools.data.households.tests.test_lifestyle_choices tools.data.households.tests.test_behavioral_choices
```

항상 새 출력 폴더를 지정한다. 별도 근거 파일은 `--reviews`로 전달한다.
차량별 근거와 평가 기준은 [근거 안내](../../../vehicles/lifestyle-evidence-v2-20261028/README.md)를 따른다.

## 구성

20,000개 재무 그룹 × 반대 취향 2개 = 40,000개 비교 사례다. 동일 재무 그룹은
학습·검증·평가 중 한 곳에만 배치한다. 브랜드·가격으로 승차감이나 성능을 추정하지 않는다.
추천 예산에 맞추어 사용자 재무 정보를 차량별로 조작하지 않는다.

`vehicle_traits.json`에는 차량별 특성값과 근거가 함께 있다.
외관 비례·각진 정도는 공식 사진의 서열 평가이고, 정원·전장·가속 성능은 근거가 있을 때만 정규화한다.
실내 단순함과 승차감 등 미확인 특성은 null이다. 세부 적용 범위와 공식 출처를 보존한다.

한쪽이라도 모르는 특성은 비교 양쪽에서 마스킹한다. 숫자 0은 저장용 자리 표시이며
나쁜 평가가 아니다. 자료가 적은 차량이 정답에서 유리하거나 불리해지지 않는다.
같은 모델군끼리의 트림 비교는 제외한다. 차량을 순환 노출하고, 근거가 있는 비교 항목을
순환 표집해 드문 가속 제원 등도 실제 비교에 등장하게 한다. 승리는 보장하지 않는다.

## 재무 조건과 취향의 역할

- `eligible-preference`: 기존 카탈로그의 양쪽 차량 모두 기존 재무 계산·필수 정원 검사를 통과한 비교다.
- `taste-only`: 위 조건을 충족하지 않은 순수 취향 비교다. 구매 가능·정원 충족·구매 의향을 뜻하지 않는다.
- 조사 단계 고급 차량 19개 사양은 검증 미완료 상태를 보존하며 항상 취향 비교에만 등장한다.
- 구매 적격 비교에서도 재무 가중치는 활성화된 비재무 가중치 합의 20%를 상한으로 한다.
  이는 사용자의 취향 중심 요구를 반영한 합성 정책이며 실제 소비자의 비중을 추정한 값이 아니다.
- 운영 추천 단계에서는 재무·정원 조건을 별도로 적용해야 한다.

출퇴근=외부 크기, 가족=확인된 정원, 주말 주행=가속 성능이라는 단순한 보조 규칙이다.
캠핑 적재량과 업무용 승차감은 근거 부족으로 점수를 만들지 않는다.
가족 적합성 전체를 정원만으로 검증하거나 가속 성능을 운전 재미로 취급하지 않는다.

## 학습 형식과 검증

`train/validation/test.jsonl`에는 원본 재무·사용자 취향·중요도·그룹·비교 차량 ID·근거 표집 항목·
마스크·특성·효용·선택 확률·추첨값·선택 정답이 있다.

각 `*_choices.npz`의 `a`, `b`는 마스킹한 11차원 특성이다. 순서는 보고서의 `feature_names`에 있다.
개인별 `weights`, 항목별 `masks`, A 선택 여부 `labels`, `financial_eligible`도 제공한다.
학습 시 중요도와 마스크를 반드시 함께 입력해야 한다. 구매 적격 학습에서는 적격 마스크도 구분한다.
기존 `PreferenceRanker`와 다른 스키마이며 모델 재학습·운영 전환은 수행하지 않았다.

`generation_report.json`은 입력 파일·생성 코드 해시, 특성 근거 확보 수량, 표집 항목,
차량별 노출, 분할별 수량과 한계를 기록한다. `saved_data_audit.json`은 저장한 JSONL과 NPZ를
다시 읽고 재무 판정·특성·마스크·효용·정답·그룹 분할을 검사한 결과와 파일 해시다.

합성 선택의 정확도는 가정한 정책에 대한 일치도다. 실제 고객 선호 정확도나 새로운 차량에 대한
일반화 성능을 의미하지 않는다. 사진 평가 역시 주관적인 모델군 수준의 검토이므로
배포 전 사람의 교차 검수와 연식·세대·트림 확인이 필요하다.
