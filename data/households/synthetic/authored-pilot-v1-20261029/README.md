# 개별 작성 파일럿 v1

사용자 30명, 차량 비교 선택 150건, 실제 카탈로그 65개 사양을 사용합니다.
`ml/test` 커밋 `a31fe22`의 행동 실험 카탈로그를 고정했습니다.

## 먼저 볼 파일

- `REVIEW.md`: 30명의 생활 배경, 재무, 취향 중요도와 각 5쌍의 선택 이유.
- `profiles.csv`, `profiles.jsonl`: 사용자 입력과 별도의 경험 중요도.
- `choices.csv`, `choices.jsonl`: 실제 차량 ID, A/B 방향, 정답, 개별 작성 이유.
- `personas.txt`: 사람이 검토할 수 있는 개별 작성 원본. 금액 단위는 만원.
- `catalog.json`: 후보 인덱스를 재현하기 위한 전체 308개 사양 스냅샷.
- `validation_report.json`: 비교 양쪽 총 300건의 재무·좌석 검사 결과.
- `manifest.json`: 데이터 출처·특징 이름·파일 해시.

## 작성 방식

상황·재무·취향을 먼저 작성하고, 사용자별 기준 후보 한 대와 비교 후보 다섯 대에 대해 선택 이유를 개별 작성했습니다. 효용 공식, 난수, 기존 모델의 예측으로 정답을 생성하지 않았습니다. 각 사용자의 다섯 비교에서는 기준 후보를 선택하며 비교 후보끼리의 순위는 정의하지 않습니다. 따라서 완전한 후보 순위/NDCG 정답이 아닙니다.

선택 방향은 기록할 때 번갈아 배치하여 A 75건, B 75건입니다. 이 비율은 기록 위치 균형이며 소비자 선택 빈도를 뜻하지 않습니다. 같은 모델은 조건을 충족하는 사양 중 가격이 가장 낮은 것을 연결하고 동점은 ID로 정합니다. 명시한 모든 비교 후보가 재무·좌석 조건을 충족해야 포장이 완료됩니다. 부적격 후보를 맞추기 위해 사용자 재무를 변경하지 않았습니다.

첫 검수에서 구매 상한 밖인 AP014의 G90 비교와 AP026의 X5 비교를 각각 K8, 스타리아 라운지 Hybrid 비교로 교체하고 이유도 다시 작성했습니다. 사용자 재무는 유지했습니다.

## 필드 의미

- `monthly_expenses`: 기존 상환·저축·이번 차량 유지비를 제외한 생활비.
- `existing_monthly_payment`, `monthly_savings`: 생활비와 별도로 차감.
- `liquid_assets`: 구매 전에 가진 유동자산. 비상금은 여기 포함되어 있으며 구매 가능액에서 제외.
- `minimum_buffer`: 차량 유지비를 낸 뒤 보존할 월 여유자금 20만원.
- `minimum_seats`: 필수 좌석. `preferred_body_type`과 충돌해도 좌석이 우선.
- `charging_available`: 집 또는 직장의 안정적 충전 접근 여부. false는 공용 충전을 절대 쓸 수 없다는 뜻이 아니며 전기차 비교를 금지하지 않습니다.
- 경험 중요도: 1=매우 낮음, 5=매우 높음. 차량별 성능·정숙성의 측정값이 아닙니다.
- `reason`: 이 사용자에게 부여한 선택 근거. 차량의 검증된 승차감·성능 제원으로 사용하지 않습니다.
- `group`: 사용자별 독립 ID. 이번 묶음에는 동일 재무 사용자 변형을 만들지 않았습니다.

재무 계산은 기존 `vehicle_matching.finance.assess`, 좌석은 `seating_status`를 사용합니다. 현금 구매·12개월 부족액 보전 정책과 카탈로그의 유지비 가정을 유지했습니다.

## 학습용 포장 범위

`train/validation/test_choices.npz`는 기존 52개 특징으로 A/B 쌍을 표현합니다. 학습 20명/100쌍, 검증 5명/25쌍, 평가 5명/25쌍으로 사용자 중복 없이 나눴습니다. 작성 순서 기반의 임시 분할로, 집단 분포를 균형화한 성능 비교용 분할은 아닙니다.

NPZ의 `features`, `comparisons`, `labels`, `profile_ids`, `vehicle_indices`는 기존 비교 학습의 배열 구조를 따릅니다. `profile_ids`는 문자열입니다. 기존 백만 프로필 학습기가 요구하는 shard manifest와는 다르므로 그 학습 명령에 바로 전달하지 않습니다.

새 경험 중요도 여섯 항목은 JSONL/CSV에 보존되어 있고 기존 52개 입력에는 들어가지 않습니다. 신규 차량 특성과 취향 표현을 모델에 연결하기 전까지 이 NPZ는 기존 특징 기준 비교용입니다. 생활 배경과 특정 디자인 호감은 설명 원문에 남아 있어, 기존 입력만으로 모든 선택 근거를 표현하지는 않습니다.

## 재포장

`ml/test` worktree 루트에서 다음 명령을 사용합니다. 출력 묶음의 파생 파일을 다시 쓰며 개별 작성 원본은 수정하지 않습니다.

```powershell
$env:PYTHONPATH = "$PWD/ml;$PWD"
& C:/workspace/final-project/ml/.venv/Scripts/python.exe -m tools.data.households.package_authored_pilot
```

검토 후 경험 입력·차량 특성의 표현을 확장하기 위한 파일럿입니다. 이번 작업에서는 모델 학습이나 서비스 교체를 수행하지 않았습니다.
