# 학습 결과를 반영한 10만 행 확장본

기존 `preference-quality-v2` 206,429행과 신규 100,000행을 합친 총 306,429행이다. 기존 원본·main은 수정하지 않으며 모든 작업은 ml/test에서 수행했다. 한글 필드와 정수 수치 형식을 유지했다.

| 분리 | 전체 행 수 |
| --- | ---: |
| 학습 | 205,673 |
| 검증 | 33,611 |
| 평가 | 67,145 |

추가분은 일반 독립 생성 70,000행, 차량별 보강 4,327행, 추가 재무 다양성 25,673행이다. 중복 제거 후 서로 다른 신규 입력이 정확히 100,000개다. 실제 최저 수량은 차량별 학습 605행·검증 62행·평가 103행이다.

## 기존 정답의 재검사

이전 실험의 부적격 추천 24건과 품질 기준 밖 추천 1,465건은 모델의 출력 오류다. 이 숫자를 근거로 평가 정답을 모델 예측에 맞춰 바꾸면 평가를 오염시키므로, 기존 선택 차량을 현재 입력과 카탈로그로 별도로 다시 판정했다.

기존 206,429행 중 필수 조건·선호 우선 단계·근접 후보 범위를 벗어난 정답은 0행이었다. 따라서 기존 행의 정답·재무·선호·분리 구분은 모두 유지했다. `change_log.csv`에 수정이 없다는 사실을 헤더만 있는 변경 기록으로 남겼다. 개선은 부족했던 다양한 학습·평가 사례를 추가하는 방식으로 수행했다.

## 추가 사례 생성

1. 약 7만 행은 기존 일반 재무·선호 생성 분포와 확률 선택을 따른다.
2. 이후 46개 기존 차량 라벨 각각 학습 최소 600행, 검증 최소 60행, 평가 최소 100행을 확보한다. 입력을 먼저 생성한 뒤, 이미 재무·정원·선호를 통과한 근접 후보 가운데 사례가 부족한 차량을 선택한다. 후보 조건을 완화하거나 선택 후 선호를 역으로 붙이지 않는다.
3. 최소 수량을 채운 이후의 나머지는 독립적인 다양한 재무 상황으로 채운다. 총 추가 수는 정확히 100,000행이다. 신규 입력 전체를 중복 검사하고 기존과 동일하거나 신규끼리 완전히 동일한 입력은 버리고 다시 생성한다.

추가 생성의 재무 배율은 일반 사례 1배, 보강·다양성 사례는 독립 추출한 1·2·3·4배다. 기존 소득 상한 월 1,500만원에 배율을 적용하므로 최대 월 6천만원의 고소득 상황도 포함된다. 재무 입력 6개와 저축·비상자금·가용자금·최소여유자금을 함께 배율 조정한다. 실제 인구 소득 분포나 차량 판매 비율을 추정한 값은 아니다. 차량별 보강은 자연 선택 빈도를 바꾸지만, 저가 차량 전체 비중을 억지로 균등하게 맞추지는 않는다. 최소 수량 확보가 학습 성능을 보장하지는 않는다.

재무 그룹을 여러 분할에 나누지 않으며 평가 전용 선호 조합은 학습·검증에서 계속 제외한다. 신규 학습·검증·평가를 독립 생성하고 기존 평가 행을 옮기지 않는다. 차 선택 후 계산하는 금액은 독립 Decimal 계산으로 검증한다. 최소 3개 적격 모델과 2개 근접 비교 후보를 유지한다.

## 파일

- `combined_training.csv`: 최종 전체 데이터.
- `additional_100000.csv`: 추가 100,000행만 포함.
- `additional_provenance.csv`: 신규 프로필별 일반/보강/재무다양성 구분과 배율. 학습 특징으로 쓰지 않는다.
- `label_coverage.csv`: 차량별 학습·검증·평가 전후 수량.
- `generation_report.json`: 생성 설정, 실제 수량, 원본 해시.
- `expansion_validation.json`: 기존 행 보존, 추가분 동일성, 신규 입력 중복, 정수 형식, 분할별 최소 수량 검증.
- `validation_report.json`: 전체 데이터의 재무·탑승·선호·분할 누수 감사.
- `examples.csv`: 파일 미리보기용 소량 예시.

재학습 시 원래 평가와 신규 일반 평가, 희소 차량 보강 평가를 구분해서 보고해야 한다. 보강 평가는 희소 차량을 의도적으로 더 포함하므로 실제 추천 빈도 추정에 쓰지 않는다. 원래 평가 결과가 이번 개발 방향에 영향을 주었으므로 이를 새롭게 보지 않은 최종 평가라고 주장하지 않는다. 모델 추천의 필수 조건 위반을 막으려면 추론 시 후보 필터와 트림별 비용 검사를 계속 적용해야 한다. 이 작업에서는 재학습을 실행하지 않았다.

## 재현

프로젝트 루트 PowerShell에서 다음 명령을 순서대로 실행한다. 생성 중에 감사를 동시에 실행하지 않는다.

```powershell
$env:PYTHONPATH='.;ml'
python -m tools.data.households.expand_quality_training
python -m tools.data.households.verify_quality_expansion
python -c "from tools.data.households.audit_quality_training import audit; from tools.data.households.expand_quality_training import OUTPUT; audit(OUTPUT)"
python -m unittest tools.data.households.tests.test_quality_expansion tools.data.households.tests.test_quality_training tools.data.households.tests.test_complete_quality
```

원래 비용·차량 제원 가정과 선호 절충 정책은 이전 v1·v2 README를 따른다. 합성 데이터의 적합성 검사는 실제 구매 선호의 검증과 구분한다.
