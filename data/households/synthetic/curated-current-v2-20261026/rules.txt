규칙 버전: curated-current-v2-20261026
서비스 정책: cash-preference-weighted-v9
작업 브랜치: ml/test (main은 수정하지 않음)
시드: 20261026

1. 데이터의 목적과 정답의 의미
이 자료는 실제 소비자의 구매 이력이 아닌 합성 입력과 현재 추천 정책의 평가값이다.
재무·선호 입력을 먼저 확정하고 차량 후보를 평가한다. 선택 차량에서 선호를 역산하지 않는다.
비교 학습의 정답은 같은 입력에서 후보 A가 B보다 현재 정책 점수가 높은지이다.
CSV의 가상 선택 차량은 확률적 예시이며, 해당 차량만 유일한 정답이라는 뜻이 아니다.
CSV 선택 차량을 이용해 분류 모델을 학습하지 않는다. 실제 순위 학습은 *_pairs.npz를 사용한다.
가상 선택 확률은 표본 후보 안의 확률이며 전체 시장 구매 확률이 아니다.

2. 원천과 계보
신규 원천: preference-population-100k-20261026-v2/profiles.jsonl, 100000행.
기존 원천: preference-financial-v4/combined_training.csv, 306429행.
기존 중간본을 모두 합치지 않는다. 같은 행이 여러 버전에 복제되어 있기 때문이다.
제외 식별자: preference-quality-v2/supplement_training.csv 전체 및
preference-quality-v3/additional_provenance.csv의 생성유형=차량별보강.
원천 파일 SHA256, 처리 당시 Git 커밋, 제외 건수는 refinement_report.json에 남긴다.
원천은 검증 완료 후 작업 폴더에서 삭제한다. 과거 원천은 원격 Git의
71d5c7c1dbc8cbf2eec93d10eac990b27ee7bfb6 커밋에서 추적 가능하다.
과거 CSV의 선택 차량/트림/점수/추천 순위/보정된 정답은 현재 정답으로 가져오지 않는다.

3. 신규 10만 행의 최초 생성 규칙
25000개 재무 그룹마다 서로 다른 선호 4개를 생성했다.
월소득: 로그정규분포(중앙값 550만원, 로그 표준편차 0.65), 150만~6000만원 제한,
1000원 단위 반올림. 구매·유지 예금: 100만~10억원 범위 로그균등 분포, 원 단위 정수.
일반 생활지출은 소득의 35~85%. 그룹의 10%는 소득 대비 100~135%의 생활지출,
다른 10%는 기존 상환 후 월 가용액이 정확히 0이 되도록 생성했다.
기존 월 상환액은 60% 확률로 소득의 0~18%, 나머지는 0원이다.
연료는 무관/휘발유/하이브리드/경유/전기/LPG, 크기는 무관/작음/중간/큼,
최소 정원은 0(무관)/2/4/5/6/7/9, 중요도는 1/3/5에서 독립 선택했다.
차량 가격이나 선택 결과에 맞춰 소득·예금·선호를 사후 보정하지 않았다.
최초 재무 그룹 기준 학습70%/검증15%/평가15% 분할을 유지하되 아래 중복 정리를 적용한다.

4. 기존 데이터 입력 변환
월소득 = 개인_평균월실수령소득_원.
월생활지출 = 개인_평균월주거비_원 + 개인_평균월기타생활소비_원.
기존월상환액 = 기존월상환액_보정전_원.
구매유지예금 = 구매투입가능자금_원. 현금성 자산 전체를 구매 자금으로 풀지 않는다.
구매투입가능자금이 현금성 자산을 넘으면 폐기한다. 보호 자금은 이미 제외된 것으로 취급한다.
기존 선호 연료·크기·최소 정원·각 중요도·지정 구매가격상한을 유지한다.
기존 중요도 1~5 정수는 그대로 허용하며 1/3/5로 억지 변환하지 않는다.
구매 전 부채 잔액은 현 추천 입력/특징에 없으므로 비교 학습에 넣지 않는다.
부채 부담은 실제 기존 월 상환액으로 반영한다. 잔액에서 새 상환액을 추측하지 않는다.
저축·비상자금·추가 월 버퍼·차량 대출·선납금·금리는 0으로 표준화한다.
연간 주행거리 15000km, 현금 구매 recommendation 모드로 표준화한다.
용도는 평가에서 제외한다. 호환 필드 commute, 중요도1은 상수이며 추천 근거가 아니다.
충전 가능 여부 역시 추천 조건으로 사용하지 않는다.

5. 폐기 규칙과 중복
월소득보정액_원 > 0인 기존 행은 제외한다. 추가 재무 보정은 하지 않는다.
특정 차량의 학습 수를 늘리려고 생성했던 차량별 보강 행은 제외한다.
필수 입력 누락, 잘못된 범주, 음수/비정수/무한 금액, 중요도1~5 밖, 정원0~9 밖은 제외한다.
현재 Profile의 모든 입력이 동일하면 한 행만 남긴다. 신규 원천을 먼저 채택한다.
폐기 원인 집계는 처리 순서상 처음 해당한 사유에만 1회 집계한다.
재무 검증 행도 사유×원래 분할별 최대2000행만 유지하고 초과 중복 유형은 폐기한다.
이 상한은 검증 자료의 크기 관리용이며 실서비스 발생 확률을 나타내지 않는다.

6. 분할과 누수 방지
재무 그룹 키 = 월소득, 월생활지출, 기존 월 상환액, 구매유지예금, 구매가격상한.
같은 재무 그룹은 선호가 달라도 같은 분할에만 둔다.
중복 원천이 여러 분할에 걸치면 평가(test) > 검증(validation) > 학습(train) 순으로 합친다.
평가 사례를 학습으로 이동시키지 않는다. 재배치 건수는 보고서에 기록한다.
카탈로그의 브랜드·모델 정렬 목록에서 매 5번째 모델을 미학습 차량 평가용으로 고정했다.
해당 모델은 학습·검증 후보 배열에서 제외하고 평가 후보 배열에는 허용한다.
구체적인 17개 모델 목록은 refinement_report.json의 held_out_models에 기록한다.
정규화 평균·표준편차는 학습 특징 행만으로 계산한다.
최적 epoch는 검증 쌍 정확도로 고르고 평가는 선택에 사용하지 않는다.

7. 재무 절대 조건
P=차량 가격, A=구매유지예금, N=월소득-생활지출-기존 월 상환액,
C=예상 월 유지비, D=max(0,C-N)로 둔다.
P <= A 이고 A-P >= 12*D일 때만 재무 적격이다.
지정 가격상한이 0이 아니면 P <= 가격상한도 충족해야 한다.
소득이 지출보다 작아도 구매 후 예금이 12개월의 부족액을 감당하면 허용한다.
미래 월급을 구매가격 한도에 더하거나 대출·할부로 구매 한도를 늘리지 않는다.
전체 후보는 같은 재무 식으로 판정하고, 저장할 적격 표본은 assess와 별도 Decimal 계산으로 대조한다.
추천 가능한 모델이 0개면 추천 없음이며, 부족한 후보를 부적격 차량으로 채우지 않는다.
최대 추천 수 = min(9, 서로 다른 적격 브랜드·모델 수).

8. 월 유지비 가정
C=연15000km/12/연비*에너지가격 + 보험100000원 + 정비60000원 + 세금25000원.
연비는 연결된 카탈로그 값을 쓴다. 없으면 연료별 가정 구간의 중간값을 사용한다.
휘발유/하이브리드/경유/LPG/전기의 단가는 각각1800/1800/1700/1100/350원이다.
누락 연비 구간은 각각8~14/14~22/10~16/6~10km/L 및 전기3~6km/kWh이다.
유지비는 현재 assess 규칙대로 센트 반올림 후 원 단위 올림한다.
취득비 추가율0, 보조금·잔존가치·선택 옵션·개인별 보험 차이는 반영하지 않는다.
가격·연비는 catalog.json의 스냅샷이며 최신 시장 가격 보장 자료가 아니다.

9. 비교 정답 점수
비용 점수=(구매가격 절약 점수 + 월 유지비 부담 점수)/2.
구매가격 절약 점수=100*clip(1-P/A,0,1).
월 유지비 부담 점수=100*(1-min(1,C/M)^2).
M은 기본적으로 max(0,N). 예금 소진으로 유지하는 경우 max(0,N+(A-P)/12).
0 나눗셈 방지 분모는 최소1원이다.
가성비 중요도가 낮으면 비용 점수의 비중만 낮춘다. 고가 차량에 별도 보너스를 주지 않는다.
크기 점수는 외장 길이 범위(작음2500~4200, 중간4200~4800, 큼4800~6000mm)와
떨어진 거리 d에 대해 100*max(0,1-d/1000). 길이 누락은50점.
연료 점수는 일치100/불일치0. PHEV는 현재 정책과 동일하게 하이브리드로 비교한다.
정원 점수=100*min(1,등록 기본 정원/희망 정원). 기본 정원이 없으면 등록 옵션의
최소 정원을 쓰고 모두 누락이면50점. 선택 옵션을 기본 가격에 확정 포함하지 않는다.
무관으로 고른 연료·크기·정원은 해당 평가 항목을 분모에서도 제외한다.
비용·선택한 연료·크기·정원 점수의 중요도 가중 평균/100을 정답 점수로 쓴다.
기존 ML 출력은 이 정답 계산에서 제외한다. 실제 사용자 만족도를 측정한 값은 아니다.

10. 후보 표본과 비교 쌍
재무 적격 후보 중 서로 다른 브랜드·모델 최대16개를 무작위 표본 추출한다.
각 모델에서는 트림/사양 하나를 무작위로 뽑는다. 차량별 수량 강제 보강은 하지 않는다.
표본은 고정 시드와 입력 해시로 재현한다. 학습/검증 표본에는 미학습 평가용 모델을 빼고 뽑는다.
같은 입력의 두 후보 점수 차이가 0.01(100점 환산1점) 이상인 쌍 중 최대8개를 쓴다.
NPZ pairs의 첫 번째 인덱스가 더 높은 정답 점수, 두 번째가 더 낮은 정답 점수다.
서로 다른 사람의 차량을 비교 쌍으로 만들지 않는다.
실제 쌍에 사용되지 않는 특징 행은 저장 배열에서 제거하고 인덱스를 다시 매긴다.
CSV 가상 선택은 표본 후보 점수의 softmax(온도0.06)로 뽑는다.
표본 후보가 비었지만 전체 적격 후보가 있으면 재무 검증용 가상 선택에만 전체 후보를 쓴다.
가상 선택과 순위 학습 쌍은 목적이 다르며 가상 선택 확률로 순위 정답을 바꾸지 않는다.

11. 최종 파일 분류
training.csv / train_profiles.jsonl / train_pairs.npz: 비교 가능한 학습 사례.
validation.csv / validation_profiles.jsonl / validation_pairs.npz: 검증 사례.
evaluation.csv / test_profiles.jsonl / test_pairs.npz: 최종 평가 사례.
financial_validation.csv / financial_profiles.jsonl: 비교 쌍을 만들 수 없는 재무 검증 사례.
재무 사유는 적격모델0개/1개, 미학습 차량 제외로 후보 부족, 점수 차이 부족으로 구분한다.
추천 없음은 재무 검증 파일에만 허용한다. 비교 학습 3개 파일은 모두 적격 선택 차량이 있다.
financial_boundary_cases.csv: 가격 ±1원, 구매 후 12개월 부족액 ±1원 경계 검증 자료.
catalog.json: 평가 차량 스냅샷. rules.txt: 이 규칙. 각 report.json: 건수·해시·검증 기록.
CSV 금액·거리·가중치·선택확률은 정수로 표기한다. JSONL/NPZ의 실수 특징과 점수는
모델 계산을 위한 값이므로 정수화하지 않는다.

12. 검증과 재학습
중복 입력0, 재무 그룹 분할 누수0, 미학습 차량 누수0, 잘못된 비교 쌍0을 확인한다.
저장 후 CSV/JSONL을 다시 읽고 선택 차량의 재무 적격을 독립 계산과 대조한다.
평가 순위 지표는 현재 규칙과의 일치도이며 실제 구매 정확도로 해석하지 않는다.
원천 삭제 전 신규 파일 검증·학습·동일 평가 사례의 이전 모델 비교를 끝낸다.
정제본만으로 재학습: ml 폴더에서
.venv\Scripts\python.exe -m vehicle_matching.train_curated_population --data-dir ../data/households/synthetic/curated-current-v2-20261026 --output outputs/models/candidate-preferences/새실행폴더
원천 재선별은 refine_population.py로 수행하며 원천은 위 과거 Git 커밋에서 별도 복구해야 한다.
