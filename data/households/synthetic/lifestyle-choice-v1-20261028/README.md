# 디자인·사용 목적·주행 취향 합성 비교 데이터

> **사용 중단:** 차량 특성까지 난수로 생성한 실험 자료로, 실제 추천 모델 학습에 사용하지 않는다.
> [근거 기반 v2](../lifestyle-choice-v2-evidence-20261028/README.md)로 대체했다.
> 아래 내용과 명령은 과거 기록이다. 현재 생성 코드는 v2 형식만 생성한다.

생성 도구: `tools/data/households/generate_lifestyle_choices.py`.

```powershell
$env:PYTHONPATH='ml;.'
ml/.venv/Scripts/python.exe -m tools.data.households.generate_lifestyle_choices --output data/households/synthetic/lifestyle-choice-v1-new --groups 20000 --seed 20261028
```

출력 경로는 새 폴더여야 한다. 같은 입력·시드로 JSONL과 학습 배열을 재현한다.
입력 파일과 생성 코드 해시는 `generation_report.json`에 기록한다.

## 차량과 자료의 신뢰 수준

기존 282개 + 공식 스포츠카 보강 22개 + 고급 차량 조사 후보 19개 = 323개 사양.
추가 조사 후보는 Porsche 911 10개, Ferrari 7개, Lamborghini 2개다.
판매 중단·보류 목록은 복원하지 않는다. 원본 조사 기록과 미확인 가격·정원은 보존한다.
고급 차량 후보는 가격 근거와 제원이 불완전하므로 항상 취향 비교에만 사용한다.
가격 미확인 값을 0원이나 추정 MSRP로 대입하지 않는다.

**외관·실내·승차감 등의 차량 특성은 실제 사진이나 리뷰를 평가한 값이 아닌 가상의 fixture다.**
모델군별로 재현 가능한 0~1 값을 생성하며 브랜드·가격·차체 형태에서 성능을 추론하지 않는다.
동일 모델군의 트림은 같은 취향 특성을 공유한다. 실제 추천에 쓰려면 이 파일을 검수된
사진 태그·제원·평가 자료로 교체하고 정답과 입력을 함께 다시 생성해야 한다.

## 사용자와 선택

- 20,000개 재무 그룹마다 원래 디자인 취향과 반대 취향 2개를 만들어 40,000개 비교를 생성한다.
- 외관 스포티함·각진 정도·실내 단순함·승차감·운전 재미·실용성 선호와 중요도를 포함한다.
- 출퇴근·가족·캠핑·주말 드라이브·업무 목적과 브랜드 선호를 포함한다.
- 용도 적합도는 단순 가정이다. 캠핑 적합도와 가족 적합도는 가상 실용성으로,
  주말 주행은 가상 운전 재미로 연결한다. 실제 적재량·견인 능력·소음 측정치가 아니다.
- 재무 입력은 차량을 보지 않고 생성한다. 원본 금융 계산과 필수 정원 검사를 모두 통과한
  기존 차량끼리의 비교만 `eligible-preference`다. 나머지는 `taste-only`로 분리한다.
- `taste-only`는 구매 가능·좌석 충족·실제 구매 의향을 주장하지 않는다. 재무 가중치는 0이다.
- 취향 비교는 부적격 차량도 포함한다. 추천 모델을 학습할 때는 `financial_eligible` 마스크로
  구분해야 하며, 운영 추천 단계에서는 재무·필수 좌석 조건을 별도로 적용해야 한다.
- 적격 비교에서만 자산 보존 점수를 보조 반영한다. 취향 가중치가 중심이며 비율은 합성 가정이다.
- 확률적 선택이므로 효용이 낮은 차량도 선택될 수 있다. 차량별 노출은 보장하되 승리는 강제하지 않는다.

동일 재무 그룹의 두 취향은 같은 분할에 들어간다. 분할은 재무 값의 해시로 결정한다.
학습·검증·평가는 새로운 재무 그룹에 대한 분할이며, 미학습 차량 일반화 평가가 아니다.
전체 정확도는 가정한 합성 정책에 대한 일치도이며 실제 고객 선호 정확도가 아니다.

## 학습 파일

각 분할의 `*_choices.npz`에는 후보 A/B의 9차원 특성 `a`, `b`, 개인별 `weights`,
A 선택 여부 `labels`, 구매 적격 비교 여부 `financial_eligible`이 들어 있다.
9차원은 6개 취향 일치도 + 용도 일치도 + 브랜드 일치도 + 자산 보존 점수다.
개인별 중요도도 학습 입력에 포함해야 서로 다른 우선순위를 학습할 수 있다.
특성 순서는 `generation_report.json`의 `feature_names`에 있다.
JSONL에는 원본 재무·선호·그룹·후보 ID·선택 확률·추첨값과 효용이 함께 있다.

기존 `PreferenceRanker`와 스키마가 다르다. 별도 학습기 구현이 필요하며 이번 실행은
재학습이나 운영 모델 전환을 수행하지 않는다.
`saved_data_audit.json`은 저장 파일 재검사의 결과와 파일 해시를 담는다.
