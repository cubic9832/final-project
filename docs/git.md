# Git 커밋 메시지 기준

## 형식

- 첫 줄은 `type: 한 줄 설명` 형식으로 작성한다. type은 아래 영문 분류를 사용하고, 콜론 뒤에 공백을 둔다.
- 첫 줄의 설명과 본문의 상세 설명은 한국어로 작성한다. 코드 식별자·파일명·기술 용어는 원래 표기를 사용할 수 있다.
- 첫 줄 다음에 빈 줄을 두고, 본문에 구체적인 변경 내용과 변경 이유를 작성한다. 필요한 경우 검증 결과도 적는다.
- 첫 줄만으로 끝내지 않고 실제 변경에 대한 상세 설명을 포함한다.

## 변경 유형

| type | 사용 기준 |
| --- | --- |
| feat | 새로운 기능 추가 |
| fix | 오류 수정 |
| docs | 문서·규칙·가이드 추가 또는 수정 |
| refactor | 동작 변경 없이 코드 구조 개선 |
| test | 테스트 추가·수정·정리 |
| style | 동작 변경 없는 코드 서식 변경 |
| perf | 성능 개선 |
| build | 빌드 설정·의존성 변경 |
| ci | CI 설정 변경 |
| chore | 위 분류에 해당하지 않는 유지보수 |

사용자에게 제공하는 UI 기능·외형 변경은 `feat` 또는 `fix` 등 변경 목적에 맞게 분류한다. `style`은 코드 서식 변경에 사용한다.

## 예시

```text
docs: 공통 에이전트 규칙과 설계 기준 추가

테스트·UI·REST API·파일 명명·설계 기준을 문서로 정의한다.
Claude·Cursor·에이전트 설정에서 같은 문서와 skill을 참조하도록 연결한다.
공통 skill 형식과 문서 참조 경로를 검증했다.
```
