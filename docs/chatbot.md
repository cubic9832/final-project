# Gemini RAG 챗봇 실행

## 화면에서 용어 설명 열기

콤파의 주 역할은 자동차·비용 용어 해설이다. 취향 테스트 결과의 차종 분류(MPV·MIDSIZE_SUV 등), 차량 상세의 차종·복합연비, 재무 추천 카드의 연료 종류·예상 월 유지비가 파란색 설명 버튼으로 표시된다. 마우스를 올리거나 키보드로 포커스하면 ‘콤파에게 물어보기’가 보이며, 클릭/Enter/Space로 챗봇을 열고 용어·차량 이름을 전달해 설명을 요청한다. 터치 화면에서는 바로 누르면 된다.

다른 요청 처리 중에는 새 용어를 대기시키며 가장 최근에 선택한 용어를 이어서 보낸다. 챗봇 닫기/Esc 시 원래 용어 버튼으로 포커스를 돌린다. 등록되지 않은 용어는 기존 텍스트로 표시한다. 회원의 재무 입력값이나 개인정보는 용어 질문에 자동 첨부하지 않는다.

다른 화면에 붙일 때는 `ExplainTerm`을 사용한다. 링크·버튼·label 안에는 중첩하지 말고 독립적인 텍스트 위치에 배치한다. 별칭은 `glossaryTerms.js`, 설명 근거는 서버의 `vehicle-terms.md`에 추가한다. 새 용어 설명 자료는 서버 재시작 후 반영된다. 현재 지식은 정의·예시·차이 중심이며 실시간 제원이나 구매 가능 판정을 제공하지 않는다.

## 구성

첫 화면의 질문은 서비스 이용 / 차종 도감 / 자동차 용어 세 카테고리로 구성한다. 첫 카테고리는 사이트 이용 방법, 나머지 두 카테고리는 차체 분류와 연료·효율 용어를 안내한다. 카테고리를 바꾸는 동작은 화면의 추천 질문만 변경하며 API를 호출하지 않는다. 추천 질문 선택 또는 직접 전송 시에만 답변을 요청한다. 헤더와 첫 인사 위의 나침반 장식은 제거했다.

응답 형식은 현재 질문의 의도에 따라 나눈다. 용어 정의를 물으면 쉬운 뜻을 설명하고 필요한 경우 비슷한 용어와 비교한다. 원인·사실 여부·사용 방법 등 일반 질문에는 결론을 먼저 직접 답한다. 예시는 필요한 경우에만 짧게 포함하며 '화면 맥락에 맞는 예시'를 고정 항목으로 만들지 않는다. 화면은 일반 텍스트로 표시하므로 마크다운 제목·강조 기호를 생성하지 않도록 지시한다. 이는 모델에 대한 지침이며 모든 응답의 형식을 강제로 보장하는 파서는 아니다.

React의 오른쪽 아래 로봇 버튼 → Spring `POST /api/v1/chat-messages` → 로컬 문서 검색 → Gemini `generateContent` → 답변 및 검색 자료 목록 순서다.
검색은 한국어 2글자 단위와 단어를 사용하는 로컬 키워드 검색이며, 질문과 최근 질문에 관련된 상위 4개 문서 조각을 제공한다. 벡터 DB·임베딩 API·Python·ML 서버 없이 실행된다. 향후 검색기와 안내 자료를 교체할 수 있다.
답변 범위 및 품질 평가 기준은 후속 작업이다. 검색 자료 목록은 모델이 실제 인용했음을 검증한 출처가 아니라 모델에 전달한 자료다.

## PowerShell 실행

Google AI Studio에서 사용할 프로젝트의 API 키를 발급받고, 기존 Spring 서버를 종료한 후 **실행할 PowerShell 창**에서 설정한다. 키를 React의 VITE 환경변수나 소스에 넣지 않는다.

```powershell
cd C:\workspace\Spring
$geminiSecret = Read-Host 'Gemini API 키' -AsSecureString
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', $geminiSecret).Password
$env:GEMINI_MODEL = 'gemini-3.5-flash-lite'
.\dev.ps1 -SkipMl
```

`http://localhost:5173`에서 로봇 버튼을 눌러 질문한다. 계정에 허용된 다른 텍스트 생성 모델을 쓰려면 `GEMINI_MODEL`을 변경하고 재시작한다. 모델·계정의 API 할당량과 요금은 Google AI Studio에서 확인한다. 자동 재시도로 중복 호출하지 않는다.
`dev.ps1`은 기존 8080 서버를 재사용하므로 설정 후 기존 서버를 반드시 종료하고 새로 실행한다.

키가 없어도 앱은 시작되며 챗봇 요청에만 503 `CHAT_NOT_CONFIGURED`가 반환된다. 키 없음 상태에서 가짜 답변을 생성하지 않는다.

## 자료 추가

기본 자료: `back/src/main/resources/chatbot/knowledge/*.md`. `## 제목` 단위로 분리하며 긴 문서는 1,200자 이하의 겹치는 조각으로 나눈다. 파일 수정 후 서버를 재시작한다. 초기 자료는 현 프로젝트의 취향 저장·회원가입·차량 조회 흐름을 설명하는 작은 안내 문서다.
외부 폴더도 지정할 수 있다.

```powershell
$env:CHATBOT_KNOWLEDGE_LOCATION = 'file:C:/workspace/Spring/data/chatbot/*.md'
```

설정 폴더의 문서는 질문에 따라 일부가 Google로 전달되므로 챗봇용 안내 자료만 넣는다. 전체 저장소·환경변수·회원 DB를 자동 수집하지 않는다.

## API 및 오류

비회원도 요청 가능하며 기존 Spring `ApiResponse` 계약을 사용한다.

```json
{"message":"취향 테스트 결과는 어떻게 저장하나요?","history":[]}
```

성공 `data`: `{ "answer": "...", "sources": [{"id":"service-guide.md#2","title":"첫 차 취향 테스트","content":"모델에 전달한 실제 자료 조각"}] }`. 화면에는 답변만 표시하며 참고 자료 목록과 본문은 노출하지 않는다. 서버의 문서 검색과 Gemini에 자료를 전달하는 기능은 유지한다.
후속 요청의 history는 user/model 순서의 완료된 대화 쌍이며 최근 12개 메시지까지만 전달한다. 질문 2,000자, 기록 메시지 6,000자로 제한한다. 서버 DB에 대화 기록을 저장하지 않는다. 브라우저 새로고침이나 초기화 버튼으로 화면 기록을 지운다.

- 400: 입력·대화 순서 오류
- 429: 동시 요청 한도 또는 Gemini 할당량 초과
- 503: API 키 미설정
- 502: Gemini 인증·모델·응답 오류
- 504: Gemini 연결 지연

실패하면 입력을 복구하므로 다시 전송할 수 있다. 서버 연결 10초·응답 45초, 화면 요청 60초 제한이다. 공용 배포 전 사용자별 호출 제한과 예산 정책은 별도로 정해야 한다. 현재 서버 동시 호출은 4개까지다.

## 검증

`back`에서 `.\gradlew.bat test`, `front`에서 `npm.cmd run build`와 챗봇 대상 lint를 실행한다. Gemini 응답은 테스트 서버로 검증하며 실제 키를 쓰는 확인은 위 환경변수 설정 후 수행한다.
