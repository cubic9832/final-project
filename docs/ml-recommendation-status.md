# 차량 추천 ML 검증 상태와 후속 과제

기준일: 2026-10-26. 작업 브랜치: ml/test.

## 목표와 현재 검증 범위

장기 목표는 실제 사용자 선택을 반영하는 개인화 추천이다. 현재 모델은 재무·선호 입력을 먼저 생성하고 현재 평가 규칙으로 만든 비교 정답을 학습한다. 현재 측정한 순위 지표는 이 규칙의 재현 정도이며 사용자 만족도나 구매 확률을 입증하지 않는다.

구매 가능 예금과 구매 후 유지비 여력은 절대 조건이다. 연료·외장 길이·정원은 기존 중요도로 평가하는 상대 조건이다. 이번 검증으로 필터나 선호 가중치를 변경하지 않았다.

## 유지하기로 한 운영 상태

| 항목 | 상태 |
| --- | --- |
| 서버 실행 스크립트 기본 모델 | candidate-preferences/20261026-100k-v1 유지 |
| 통합 모델 | 20261026-refined-v1, 실험·추가 검증용 보존 |
| 보정 sigmoid | 실험안으로 보존, 운영 미적용 |
| ML·선호 가중치 및 재무 정책 | 유지 |
| 실제 개인화 개선 | 독립적인 검증 근거 없음 |

위 모델 경로는 serve-candidates.ps1의 기본값 기준이다. 실제 실행 프로세스는 환경변수나 실행 인자로 다른 경로를 사용할 수 있으므로 배포 기록에 최종 적용 경로와 가중치 해시를 남겨야 한다.

## 확인된 기술 결함과 해결 범위

PreferenceRanker.predict는 원본 출력에 float32 sigmoid를 적용한다. 큰 양수 출력이 모두1.0으로 포화되면 서로 다른 차량의 순위 정보가 손실된다.

독립 순위 평가에는 ranking_scores의 원본 출력을 사용하도록 수정했다. 동일한300개 입력에서 원본 출력 NDCG@3은 이전0.9977, 통합0.9989였다. 차이0.0012의 통계적 유의성이나 다른 분포에서의 개선은 입증하지 않았다. 이전의 변환 후 지표0.9188과0.8325를 학습 성능 하락의 증거로 해석했던 결론은 철회한다.

**실제 서비스 경로의 포화는 미해결 기술 부채다.** CandidateService는 여전히 predict의 변환 점수를 명시 평가와 합산한다. 순위 평가 수정은 실제 서비스의 점수 결합 방식 수정과 다르다. 기존 운영 유지 결정이 포화 문제의 해결이나 정상화 완료를 뜻하지 않는다.

보정 sigmoid는 실험 표본에서 포화를 없앴지만, 그 신호를 기존 점수에 합산했을 때 추천 품질이 좋아졌다는 독립적인 근거는 없다. 원본 출력을 기존0~1 점수 자리에 그대로 대입하지 않는다. 점수 변환 변경과 ML 가중치 변경은 각각 별도 실험으로 관리한다.

## 실험 결과와 해석

기존300개와 별도300개, 총600개의 규칙 기준선 대비 보정 sigmoid 결과를 검토했다.

- 상위3대 모델 순서 변경137개, 모델 구성 변경56개.
- 선호 점수 하락 역전이 있는 사례9개, 완전 충족 조건 상실이 있는 사례7개.
- 중요도4~5 조건의 완전 충족 상실0개, 재무 적격 위반0개. 이번 표본에서의 결과다.
- 역전154쌍 중139쌍은 측정된 비ML 항목에서 추가 이점 없이 ML 기여 차이로 순서가 바뀌었다.
- 최종100점 척도의 비ML 기여 차이는 중앙값0.0162점으로 대부분 근소했다. 이를 모두 심각한 오류로 판정하지 않는다.

X5와 티볼리는 가격·크기·정원 사이의 실제 절충이 있었으나, 명시 평가에서는X5가0.2245점 앞섰다. ML 기여 차이0.2751점으로 티볼리가 최종0.0506점 앞섰다. 경제적 이점은 이미 규칙 점수에 포함돼 있다. 중복 반영인지 근사 오차인지는 이 수치만으로 확정하지 않는다. 어느 경우든 새로운 사용자 취향을 발견한 증거로 설명하지 않는다.

서버가9대를 반환해도 사용자가 처음3대만 봤다면9대 모두를 노출로 기록하지 않는다. 접힌 영역이나 더보기 이후 후보는 실제로 보였을 때 기록한다. 재렌더링·재시도로 같은 노출이나 행동이 중복 집계되지 않게 이벤트 식별자를 둔다.

사용자가 선택하지 않은 후보도 평가 스냅샷에 남긴다. 다만 미노출 차량을 비선호 정답으로 취급하지 않는다. 클릭·비교·저장은 구매나 만족도와 구분하고, 실제 선택·구매는 그 사실이 확인된 이벤트만 사용한다. 연락처 등 식별 정보 대신 분석용 식별자를 사용하고 입력 스냅샷은 필요한 권한과 보존 범위 안에서 관리한다.

## 후속 평가 기준

노출 순위가 행동에 영향을 주므로, 관측된 클릭 수만으로 차량 선호나 추천 정책의 우열을 판단하지 않는다. 노출 위치·후보 집합·정책 버전을 함께 분석한다. 무작위 노출 실험을 도입하는 경우에만 실제 할당 확률을 별도로 기록하며, 결정적 추천에 임의의 노출 확률을 붙이지 않는다.

현재 합성 규칙 재현 결과와 향후 사용자 행동 기반 평가는 별도로 보고한다. 실제 선택 자료나 독립적인 전문가 평가가 확보되기 전에는 ML에 의한 규칙 순위 역전을 개인화 개선으로 홍보하지 않는다.

당장의 상태는 기존 추천 유지, 보정 방식 실험 보존, 서비스 포화 기술 부채 명시다. 다음 기능 작업은 동일 합성 평가의 반복이나 임의 가중치 조정보다 위 관측 기반 구축을 우선한다.
