# 회원 전용 첫 차 취향 테스트

## 진입 흐름

- 상단에는 기존 `차량 비교` 단일 메뉴를 유지한다.
- 일반 회원가입 완료 팝업에서 `로그인하고 취향 테스트` 또는 `나중에 하기`를 선택한다. 기존 로그인 절차는 유지한다.
- 구글 신규 가입은 로그인까지 완료되므로 취향 테스트 안내 화면으로 이동한다. 여기서 시작하거나 나중에 할 수 있다.
- `/taste-test`는 로그인 필수이며, 마이페이지의 `내 첫 차 취향 알아보기`에서 다시 진입한다.

## DB와 저장 정책

- Flyway V10: 질문 버전·질문·선택지·선택지 점수·분기 규칙·결과 유형·대표 차량·회원별 현재 취향의 8개 테이블과 첫차 질문 시드를 생성한다.
- V11: `saved_at`을 DATETIME(6)으로 확장한다. 적용한 마이그레이션은 수정하지 않는다.
- 기존 V1~V9 및 기존 회원 데이터는 유지된다. 개발 서버 시작 시 새 마이그레이션이 적용된다.
- 회원별 현재 취향은 최대 한 행이다. 테스트 시작·건너뛰기·결과 확인은 DB에 취향을 저장하지 않는다. 결과에서 저장을 눌렀을 때만 생성·갱신한다.
- 재검사는 기존 취향을 자동 변경하지 않는다. 덮어쓰기 확인 후 저장하며, 다른 탭에서 먼저 갱신한 경우 409로 거절한다. 같은 답변의 PUT 재전송은 동일 결과와 저장 시각을 반환한다.
- 질문과 규칙은 DB에서 조회한다. 클라이언트의 임의 결과나 회원 번호는 받지 않으며, 서버가 8개 답변의 질문 순서·선택지 소속·분기를 검증하고 결과를 계산한다.
- 회원 탈퇴 시 현재 취향도 외래키 CASCADE로 삭제된다.
- 질문을 변경하려면 새 버전과 시드를 추가한다. 동점은 유형의 `display_order` 순으로 결정하며 프론트와 서버가 같은 순서를 사용한다.
- 브라우저에는 회원·버전별 진행 중 답변만 sessionStorage로 임시 저장한다. 기존 localStorage 취향은 DB로 자동 이관하지 않는다.

## API

모든 경로는 JWT 인증이 필요하다. 회원 ID는 인증 토큰에서 추출한다.

| 메서드 | 경로 | 응답 |
| --- | --- | --- |
| GET | `/api/v1/members/me/taste-test` | 200: 공개 중인 질문·규칙·유형·대표 차량 |
| GET | `/api/v1/members/me/current-taste` | 저장값 있으면 200, 없으면 본문 없는 204 |
| PUT | `/api/v1/members/me/current-taste` | 200: 서버가 검증·저장한 현재 취향 |

PUT 요청은 `version`, 8개의 `{ questionId, optionId }` 답변, `expectedSavedAt`(첫 저장은 null)을 받는다. 결과는 `version`, `answers`, `primary`, `savedAt`이다. 200 성공 응답은 다른 Spring API와 동일하게 `ApiResponse.ok`의 `data`에 결과를 담으며, 프런트는 `response.data.data`를 읽는다. 저장값이 없는 GET의 204에는 본문이 없다. 입력·분기 오류는 400, 버전·동시 갱신 충돌은 409이며 공통 `ApiResponse.fail`의 `error.code`와 `error.message`로 반환한다(`application/json`). 인증 실패도 같은 실패 봉투를 사용한다.

## 검증

- Java 컴파일 및 Spring/DB 통합 테스트: 미인증 차단, 최초 저장 없음, 서버 계산, 잘못된 분기·구버전 거절, 회원별 격리, 명시적 덮어쓰기, 반복 PUT, 회원 탈퇴 정리.
- 실제 DB 카탈로그의 65,536개 경로를 검증하여 모든 경로가 8문항·문항별 4개 선택지로 끝나는지 확인한다.
- 임시 저장은 회원·버전 격리와 손상된 답변 복원 거부를 검증한다.

백엔드 검증은 `back`에서 `.\gradlew.bat test`로 실행한다. `taste/controller/TasteApiControllerTests`는 공통 응답 봉투·204·입력 오류·충돌을, `taste/service/TasteServiceTests`는 회원별 저장·멱등성과 충돌 방지를 검증한다. 컨텍스트 기동 테스트에는 기존 MySQL 접속이 필요하다. 데이터와 이미 적용된 Flyway SQL은 검증을 위해 초기화하지 않는다.
